??? question "Q1. 停止問題があるのに Coq は問題ないのか？"

    *(2026-06-28)*

    **A.** Coq は「停止することが証明できるプログラムしか書けない」ように設計することで、停止問題を**土俵ごと回避**している。

    #### 停止問題の「対象」を確認する

    [§4b 停止問題](AL-Models.md#decidability) が「決定不能」なのは、**チューリング完全な系**における「任意のプログラム P と入力 I」に対する話。チューリング完全であるということは「無限ループするプログラムも書ける」ということを含む。

    #### Coq が取った選択：チューリング完全でないことを選ぶ

    Coq は [Church-Turing 命題](AL-Models.md#church-turing) で言う「TM と等価な計算能力」を**わざと持たない**。

    | 系 | 任意の再帰 | 停止問題 | 論理的一貫性 |
    |---|---|---|---|
    | チューリング機械・Python・Haskell | 書ける | 決定不能 | — |
    | **Coq** | 書けない（停止性が証明できる再帰のみ） | **そもそも発生しない** | 保証される |

    #### Coq の仕組み：構造的再帰チェック

    `Fixpoint` で再帰関数を定義すると、Coq の **停止性チェッカー** が構文的に「再帰呼び出しのたびに引数が構造的に小さくなるか」を検査する。

    ```coq
    Fixpoint plus (n m : nat) : nat :=
      match n with
      | O    => m
      | S n' => S (plus n' m)   (* n' は n より構造的に小さい → OK *)
      end.
    ```

    この検査は**決定可能**（チューリング完全な計算の停止判定とは別問題）。停止性チェッカーが弾いたプログラムは Coq に型付けされない。

    #### 強正規化定理（Strong Normalization）

    Coq の型理論（Calculus of Inductive Constructions, CIC）は**強正規化**が定理として証明されている：

    > well-typed な Coq の項は**必ず有限ステップで正規形（簡約の止まった形）に到達する**。

    つまり「Coq プログラムが停止するか」は答えが常に「停止する」。停止問題が発生する余地がない。

    #### 代償：チューリング完全でない

    タダではない。一部の**計算可能関数を Coq のコアに直接書けない**。

    - 例：停止するか不明な再帰（Collatz 数列 `f(n) = if n=1 then 0 else f(...)` など）は `Fixpoint` では書けない。
    - 回避策：燃料パラメータ (`Fixpoint collatz (fuel n : nat)`)、`Program Fixpoint`（well-founded 証明付き）など。

    #### Curry-Howard 対応との接続

    Coq では「証明 = プログラム、命題 = 型」（[Curry-Howard 対応](AL-Models.md#equivalent-models)）。もし非停止プログラムを書けると、任意の命題 `P` の「証明」として使えてしまう → **論理が矛盾**（False を証明できる）。停止性制約は論理的一貫性を守るための本質的な条件。

    #### まとめ

    - 停止問題は「任意のプログラムを受け入れる系」の問題。Coq は停止するプログラムしか受け付けないことで問題を回避している。
    - 代償としてチューリング完全ではないが、**定理証明器としての一貫性**を確保するためにその代償は必須。
    - Lean 4・Agda・Idris（total モード）も同様の設計思想。

??? question "Q2. 「オートマトン」という言葉の原義・語源は？"

    *(2026-06-28)*

    **A.** ギリシア語 **αὐτόματον**（automaton）に由来し、「**自ら動くもの**」という意味。

    #### 分解

    | 要素 | ギリシア語 | 意味 |
    |---|---|---|
    | **auto-** | αὐτο- | 「自分自身」 |
    | **-maton** | -ματον | 「動こうとするもの・意志をもつもの」 |
    | 合計 | αὐτόματος | **「自ら動くもの・自力で行動するもの」** |

    - **auto-**（αὐτο-）は現代語に多数残る：automobile（自動車）・automatic（自動）・autonomy（自律）・autopilot・autism など。
    - **-maton**（-ματον）はギリシア語動詞 **μάομαι**（maomai、「～しようと欲する・求める・意志する」）の完了受動分詞形に由来。「自分の意志で行動する」というニュアンスを持つ。

    #### 原義と歴史的用例

    ホメロスの『イリアス』にすでに登場する。「天の門が**自ら開いた**（αὐτόματοι）」や、鍛冶神ヘパイストスが作った「**自ら動く**黄金の侍者たち」など——外部の力なしに動くものへの形容語として使われた。

    その後、西洋では機械仕掛けの人形（ぜんまい仕掛けのからくり）を指す語として近世まで使われ、CS では「**遷移規則に従って自ら入力を処理する抽象機械**」という意味で使われている。原義とぴったり合致している。

    #### 複数形 automata

    CS で "finite **automata**"（オートマタ）と言うのは、ギリシア語・ラテン語の中性複数形（-on → -a）を使っているため。「オートマトン 1 台」→ automaton、「複数台」→ automata。

    #### CS との対応

    [§1 形式オートマトン](AL-Models.md#formal-automata) が扱う DFA・NFA・PDA・TM は、どれも「入力記号を与えると遷移規則に従って**自ら状態を変えながら処理を進める**」機械。「自ら動く」という原義がそのまま生きている。

??? question "Q3. 現実には全てはLBAでは？（物理的な計算機はどのモデルに対応するか）"

    *(2026-06-28)*

    **A.** 実は LBA でもなく、正確には **FSA（有限オートマトン）**。ただしそれでも TM を使う理由がある。

    #### 現実の計算機はLBAではなくFSA

    LBA は「**入力長 n に比例した**テープを使う」機械（→ [§1c](AL-Models.md#formal-automata)）。しかし現実の計算機のメモリ量は入力の大きさに連動していない——64GB の RAM は入力が 1 バイトでも 1TB でも同じく 64GB。

    現実の計算機（メモリ上限 N ビット固定）は正確には：

    | 観点 | 結論 |
    |---|---|
    | 使える状態数 | 2^N 通り（N ビットのメモリが取りうる全状態） |
    | モデルとしての分類 | **巨大な FSA** |
    | LBA との違い | LBA はメモリが入力長に比例して伸縮する。物理計算機は固定 |

    つまりユーザーの直感はほぼ正しく、「LBA より制限が強い FSA」が現実に近い。

    #### それでも TM を使う理由

    **1. 「原理的に解けるか」を問いたい**

    Church-Turing 命題（[§5](AL-Models.md#church-turing)）が問うのは「**メモリを好きなだけ使えると仮定したとき**、アルゴリズムが存在するか」。現実のハードウェア制約を外して「計算可能性そのもの」を議論する枠組みが TM。

    **2. アルゴリズムはスケールして動くべき**

    「このコードは今のマシンで n ≤ 10⁶ に答えを出す」ではなく「**任意の n に対して正しく動く**」かを論じたい。固定メモリ（FSA）で論じると、n が大きくなると「メモリ不足で停止する」ことが正しい動作と区別できない。

    **3. 天文学的 FSA は扱えない**

    64GB マシンの状態数 2^(64×10⁹×8) を FSA として扱おうとすると遷移表が宇宙に収まらない。TM は「テープが必要な分だけ伸びる」と抽象化することで、この問題を回避しながら計算の本質を分析できる。

    #### 面白い帰結：停止問題は物理的には決定可能

    物理的に固定したマシン（N ビット・固定の FSA）に限定すれば、停止問題は**原理的に決定可能**になる：

    - 状態数は 2^N で有限。
    - プログラムを動かして同じ状態が 2 回現れれば無限ループ確定、受理状態に到達すれば停止。
    - 最大 2^N ステップ以内に判明する。

    しかし「原理的に決定可能」≠「実用的に解ける」：

    - 64GB マシンで 2^(64×10⁹×8) ステップ待つのは宇宙の寿命より遥かに長い。
    - 静的解析ツールがすべてのプログラムのバグを検出できない現実の壁は、チューリング計算量の限界ではなく**指数時間の壁**。

    #### まとめ

    - 物理計算機の正確なモデル：**巨大な FSA**（LBA でも TM でもない）。
    - TM を使う理由：ハードウェア制約を外して「原理上の計算可能性」と「任意サイズへのスケール」を論じるための抽象化。
    - 停止問題は「物理的に固定したマシン」では決定可能だが、状態空間が天文学的なので実用上は意味をなさない。

??? question "Q4. 形式オートマトンの「形式」とはどういう意味か？"

    *(2026-06-28)*

    **A.** 英語 **formal** の訳語で、「**意味（meaning）を問わず、記号の形・構造だけを扱う**」という意味。

    #### 語源

    ラテン語 **forma**（「形・型」）が祖語。数学・論理学で "formal" は「記号の意味内容は脇に置き、**形（構造・規則）だけで操作・定義する**」という意味で使われる。

    #### 形式的 vs 非形式的

    | | 形式的 (formal) | 非形式的 (informal) |
    |---|---|---|
    | **言語** | 形式言語：アルファベットと生成規則で厳密定義された文字列の集合 | 自然言語：日本語・英語など（文脈・意味・曖昧性を含む） |
    | **証明** | 公理と推論規則だけで記号を変形（意味を使わない） | 「直感的に明らか」「図を見れば分かる」という説明 |
    | **文法** | CFG の生成規則 `A → α`（記号の置き換え規則） | 「名詞句の後に動詞句が来る」という自然言語の説明 |
    | **オートマトン** | (Q, Σ, δ, q₀, F) の 5 組で完全・一意に定義 | 「こういう動きをする機械」という説明 |

    #### 「形式オートマトン」への適用

    DFA を例にすると：

    - 入力文字列 `"ab"` が何を「意味する」かは問わない。
    - 状態 q₀ で `'a'` を読んだら q₁ へ、q₁ で `'b'` を読んだら q₂ へ——という**記号操作のルール（δ）だけで受理・拒否を決める**。
    - これが「形式的」：意味ではなく**形（構造・遷移）**が全て。

    この性質があるから、「この DFA が受理する言語は何か」「この言語は正規言語か」といった**数学的証明ができる**。意味が絡むと曖昧になって証明できない。

    #### 日本語「形式」のニュアンス

    「形式」＝ 形（かたち）＋ 式（規則・式）。「**内容（意味）**」に対する「**外側の形・構造・規則**」という意味で、英語の formal のニュアンスとぴったり対応している。

    日常語の「形式的な挨拶」（中身のない、型通りの挨拶）という使い方もここから来ている——「意味より形を重視する」という点が共通。
