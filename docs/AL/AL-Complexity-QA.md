??? question "Q1. little-o / little-ω / little-θ の読み方は？"

    *(2026-06-23)*

    **A.** 小文字版は "**little-**"（または "small-"）を付けて、大文字版（big-）と区別して読む。

    | 記法 | 英語 | 日本語 |
    |---|---|---|
    | **o(g)** | "little-o of g"（small-o） | リトルオー（スモールオー） |
    | **ω(g)** | "little-omega of g" | リトルオメガ |
    | **θ(g)** | "little-theta of g" | リトルシータ |

    - 大文字 `O/Ω/Θ` は "**big-**oh / big-omega / big-theta"、小文字 `o/ω/θ` は "**little-**…"。**音だけでは `O` と `o` が区別できない**ので、会話で計算量を話すときは "big" / "little" を明示するのが実用上のコツ。
    - ω・θ は文字自体が「オメガ」「シータ」（ギリシャ文字）。"little-" は「小文字版だよ」という目印にすぎない。
    - 意味の対応（→ [§7 本文](AL-Complexity.md#little-notations)）: 大文字 `O/Ω/Θ` が **≤・≥・=**、小文字 `o/ω` が **<・>**（タイトな等号を含まない厳密な上界・下界）。

    関連: [§7 little-o / little-ω / little-θ](AL-Complexity.md#little-notations)、[§2 漸近記法 O/Ω/Θ](AL-Complexity.md#asymptotic-notation)

??? question "Q2. 多項式時間とは？"

    *(2026-06-23)*

    **A.** アルゴリズムの実行時間が、入力サイズ `n` の**多項式** `O(nᶜ)`（`c` は定数）で上から抑えられること。`O(n)`・`O(n log n)`・`O(n²)`・`O(n³)` などはすべて多項式時間。`O(2ⁿ)`（指数）や `O(n!)`（階乗）は**多項式時間ではない**。

    | | 例 | 実用上 |
    |---|---|---|
    | **多項式時間** `O(nᶜ)` | 二分探索 O(log n)、ソート O(n log n)、ガウス消去 O(n³) | 現実的に解ける（**tractable**） |
    | 指数時間以上 `O(2ⁿ)`〜 | 部分集合の全列挙、素朴な TSP | n が少し増えるだけで破綻 |

    - **なぜ「多項式以下＝実用的」と線引きするのか**: ① `O(nᶜ)` までは n の増加に現実的についていけるが、`O(2ⁿ)` を超えると[少しの増加で宇宙年齢を超える「崖」](AL-Complexity.md#complexity-classes)がある。② 多項式は**合成・加減乗算で閉じている**（多項式の多項式・和・積はまた多項式）ので、「多項式時間の前処理＋多項式時間の本処理」がまた多項式に収まり、議論の単位として頑健。③ 計算モデル（Turing機械・RAM等）の違いも多項式の係数差に吸収され、機種非依存の区切りになる。
    - **クラス P との関係**: [**P ＝ 多項式時間で解ける問題のクラス**](AL-Complexity.md#p-np-npc)。「扱いやすい (tractable)」の正式な定義がこれ。`NP` は「答えを渡されれば多項式時間で**検証**できる」クラスで、`P ⊆ NP`。
    - **落とし穴 — 擬多項式時間 (pseudo-polynomial)**: 入力サイズ `n` は「数値そのもの」ではなく「その**ビット長 = log₂W**」で測る。0/1 ナップサックの DP は `O(nW)` で一見多項式に見えるが、`W` は入力長 `log₂W` に対して**指数的に大きい**ので、真の入力サイズでは指数。これを擬多項式時間と呼ぶ（→ [§1c 入力サイズ](AL-Complexity.md#input-size)、[AL-Foundational-Quiz Q23](AL-Foundational-Quiz.md#quiz-q23)）。

    関連: [§3 基本計算量クラスと代表例](AL-Complexity.md#complexity-classes)、[§6 扱いやすさ／扱いにくさ（P・NP・NP完全）](AL-Complexity.md#tractability)、[擬多項式（バケツソート/Pseudo）](AL-Foundational-QA.md#q11)

??? question "Q3. 複雑性クラス（complexity class）とは？"

    *(2026-06-23)*

    **A.** **「ある計算資源（時間・空間）の枠内で解ける問題をひとまとめにした集合」**。＝「この道具立てで現実的に届く範囲はここまで」という線引き。日本語では文脈で **2 つの意味**で使われるので注意。CS2023 も両方を "complexity class" と呼んでいる。

    | | 何を分類するか | 例 | 本文 |
    |---|---|---|---|
    | **(1) 増加率クラス**<br>(Foundational Complexity Classes) | **アルゴリズム**の実行時間が n とともにどう伸びるか | O(1)・O(log n)・O(n)・O(n log n)・O(n²)・O(nᶜ)・O(2ⁿ)・O(n!) | [§3](AL-Complexity.md#complexity-classes) |
    | **(2) 問題のクラス**<br>(P, NP, …) | **問題**そのものが、与えた資源で解ける/検証できるか | P・NP・NP完全・PSPACE・EXP | [§6](AL-Complexity.md#tractability) |

    - **(1) は「アルゴリズムが速いか」、(2) は「問題が解けるか」**——主語が違う。「二分探索は O(log n) だ」は (1)、「最短経路問題は P に属する」は (2)。同じ問題でも実装次第で (1) の増加率は変わるが、(2) は**問題に内在する難しさ**を指す。
    - **(2) を分ける軸は 3 つ**: ① **資源**＝時間か空間か、② **量**＝多項式か指数か、③ **計算モデル**＝決定性か非決定性か（当てずっぽうを許すか）。この組み合わせでクラスが決まる。
        - **P** = 決定性・多項式**時間**で**解ける**。
        - **NP** = 非決定性・多項式時間（＝答えを渡されれば多項式時間で**検証**できる）。`P ⊆ NP`。
        - **NP完全** = NP の中で最難（NP の全問題がここへ多項式時間で帰着できる）。
        - **PSPACE** = 多項式**空間**で解ける。`P ⊆ NP ⊆ PSPACE`。
        - **EXP** = 指数時間で解ける。
    - **なぜクラスにまとめるのか**: 個々のアルゴリズムの定数倍や機種差を捨てて、「**この問題は本質的にどれだけ難しいか**」を機種非依存に語れるから。新しい問題に出会っても「既知のどのクラスに入るか」を示せば、解ける見込み・取るべき戦略（厳密解 / 近似 / ヒューリスティック）が一気に決まる（→ [§6 NP完全だと分かったら何をするか](AL-Complexity.md#tractability)）。

    関連: [§3 基本計算量クラス（増加率）](AL-Complexity.md#complexity-classes)、[§6a P・NP・NP完全（問題のクラス）](AL-Complexity.md#p-np-npc)、[多項式時間（Q2）](#q2)

??? question "Q4. P と NP / NP と NP完全 / NP困難 と NP完全 — それぞれの違いは？"

    *(2026-06-24)*

    **A.** 3 つの違いは、いずれも **「解けるか・検証できるか」** と **「NP に属するか・帰着で最難か」** の 2 軸で説明できる。包含関係（P ≠ NP を仮定）は **P ⊆ NP、NP完全 = NP ∩ NP困難**。

    ### ① P と NP の違い —「解ける」か「検証できる」か

    | | 定義 | 直感 | 例 |
    |---|---|---|---|
    | **P** | 多項式時間で**解ける** | 自分で答えを**作れる**ほど速い | ソート、最短経路、二分探索 |
    | **NP** | 答えを渡されれば多項式時間で**検証できる** | 答え合わせだけなら速い | SAT、TSP（判定版）、ナップサック（判定版） |

    - **解ける ⇒ 検証できる**ので **P ⊆ NP**（解ける問題は、解いてみせれば検証も当然できる）。
    - 逆（検証できれば解けるか＝ **P = NP か**）は**未解決**（ミレニアム懸賞問題）。だから「P ≠ NP が証明されている」とは書かない。
    - NP の N は **N**ondeterministic（非決定性）。「**当てずっぽうで答えを引いて (N)、多項式時間で検証 (P)**」が NP の正体。数独は解くのは大変でも、解を渡されれば一瞬で確認できる。

    ### ② NP と NP完全 の違い —「集合」か「その中の最難グループ」か

    - **NP** は問題の**集合**で、中身はピンキリ。P に入る易しい問題から、NP完全の難問まで含む（**P ⊆ NP**）。
    - **NP完全 (NP-Complete)** は、その NP の中で**最も難しいグループ**。条件は 2 つ:
        1. **NP に属する**（検証は多項式時間でできる）、かつ
        2. **NP のすべての問題がそこへ多項式時間で帰着できる**（だから「1 つでも NP完全問題が多項式時間で解ければ NP 全体が解け、P = NP になる」）。
    - つまり **NP完全 ⊊ NP**。最初に NP完全と証明されたのが **SAT**（[Cook-Levin の定理](AL-Complexity.md#tractability)）で、以後の問題は「SAT からの帰着」で芋づる式に示せる。

    ### ③ NP困難 と NP完全 の違い —「NP に属するか」だけが分かれ目

    | | NP の全問題が帰着できる（最難の下界） | NP に属する（検証が多項式時間） |
    |---|---|---|
    | **NP困難 (NP-Hard)** | ✅ 必要 | **不問**（属さなくてよい） |
    | **NP完全 (NP-Complete)** | ✅ 必要 | ✅ **必要** |

    - **NP完全 = NP困難 ∩ NP**。NP困難から「NP に属する」条件を**外した**のが NP困難。
    - だから NP困難には **NP の外の問題**も入る: 最適化版 TSP（「最短経路を**1 つ出せ**」は判定問題でなく検証が自明でない）、さらに**停止性問題のような決定不能問題**まで。「少なくとも NP完全と同じだけ難しい、ただし NP に収まるとは限らない」が NP困難。
    - 構図で覚える: **NP困難＝難しさの『下界』（少なくともこれだけ難しい）／ NP＝『上界』（検証は多項式でできる）**。両方を満たす交点が NP完全。これは [§2 の O＝上界・Ω＝下界](AL-Complexity.md#asymptotic-notation)と同じ「上下から挟む」発想（学習成果12）。
