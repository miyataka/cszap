## 2026-07-27 出題分（OS-Protection / OS-Process / OS-Memory レベル判定クイズ 全12問中 Q9–12）

!!! abstract "総合スコア"

    | 評価帯 | 問数 | 該当 |
    |---|---|---|
    | 良（0.8） | 1 | Q10 |
    | 低（0.3） | 1 | Q9 |
    | ゼロ（0.0） | 2 | Q11, Q12 |

### 講評

- **強み**: Q10（デマンドページング／ページフォルト）は正確。
- **弱み**: Q9（TLB）は「MMU・アドレス変換」全般の説明に終始し、**TLB固有の役割（変換結果のキャッシュによる高速化）に届いていない**。Q11（スラッシング）・Q12（Dirty COWとユニット横断の統合問題）は未回答——特に Q12 は Protection ユニットとの接続を問う統合設問だっただけに、両ユニットとも手薄な今の状態を象徴している。
- **次の一手**: Q9 は「なぜページテーブルを毎回メモリから引かず TLB を使うのか＝速度」という一点を補えば大きく伸びる。Q11・Q12 は本文（OS-Memory §4, §8）を読み直してから再テストするのが効率的。

??? question "Q9. TLB（Translation Lookaside Buffer）とは何か。なぜ必要か。　【採点 0.3 / 1.0】"

    **本人の回答**

    > 仮装メモリと物理メモリのアドレス変換のために必要．プロセスに他のプロセスのメモリを見せないように分離するために必要

    **模範解答**

    変換表（ページテーブル）を**毎回メモリから引くと遅すぎる**ので、MMU が変換結果をキャッシュしておく仕組みが TLB。直近使ったアドレス変換をキャッシュに保持し、ヒットすれば高速に物理アドレスへ変換できる。

    **採点 0.3** — 「アドレス変換」「分離」は MMU 全般の目的としては正しいが、これは**ページテーブル（MMU）そのものの役割**であり、**TLB固有の役割（変換をキャッシュして高速化する）に言及がない**。設問は TLB 固有の存在意義を問うている点に注意。

??? question "Q10. デマンドページングとページフォルトの関係を説明せよ。　【採点 0.8 / 1.0】"

    **本人の回答**

    > デマンドページングは必要になったときにページを取得しにいく．ページフォルトはそのページが必要なときにメモリ上にないこと

    **模範解答**

    **デマンドページング**：ページは触られたときに初めて割り当て・読み込みする。**存在しないページへのアクセスはページフォルト**（例外）となり、OS がそれを処理（ディスクから読み込み・フレーム割り当て）した上でアクセスを再実行する。

    **採点 0.8** — 両者の関係を正確に説明。「例外として処理され、処理後にアクセスを再実行する」という後段まで書ければ満点。

??? question "Q11. スラッシング（thrashing）が起きるメカニズムと、その対策を説明せよ。　【採点 0.0 / 1.0】"

    **本人の回答**

    > （未回答）

    **模範解答**

    全体のフレームが足りず、**ページ入れ替えばかりで仕事が進まない**状態。実行に「いま必要なページ集合」（ワーキングセット）がメモリに収まらないのが原因。対策は**多重度を下げる**（中期スケジューラで実行中プロセス数を減らす）か、**メモリを増やす**しかない。

    **採点 0.0** — 未回答。

??? question "Q12. Dirty COW脆弱性は何の機構のバグだったか。そして、なぜ「競合状態のバグ」がそのまま「権限昇格」につながったのか。OS-MemoryとOS-Protection両方の内容を結びつけて説明せよ。　【採点 0.0 / 1.0】"

    **本人の回答**

    > （未回答）

    **模範解答**

    **コピーオンライト (COW)**（[OS-Memory §8](OS-Memory.md#virtual-memory-services)）——fork 時にページを共有し、書いた瞬間だけ複製する機構——の**競合状態（race condition）**のバグ。COW 処理のタイミングを突くことで、本来読み取り専用のはずのファイルに書き込めてしまった。これは並行性バグ（[OS-Concurrency](OS-Concurrency.md)）が [OS-Protection §3](OS-Protection.md#real-vulnerabilities) の言う「実在OSの重大脆弱性」として現れた例で、メモリ管理の最適化機構（COW）が**そのまま権限昇格の攻撃経路**になった——ユニットをまたいだ理解が問われる典型例。

    **採点 0.0** — 未回答。3ユニットを横断する統合設問であり、今回の未回答の中でも特に復習優先度が高い。
