### 講評

- Q13 は5ユニット横断クイズの中でもっとも総合的な設問（CPU・メモリ・デバイスの3資源すべてを問う）だっただけに、未回答は惜しい。[OS-Virtualization](OS-Virtualization.md) は「保護（Protection）・プロセス（Process）・メモリ（Memory）の学習が合流する総仕上げ的なユニット」と位置づけている通り、前提知識（ページテーブル・保護リング・プロセス分離）が揃っていないと答えにくい設問でもある。次回はまず本文 §1・§2・§3・§9 を読み直してから再テストするのが効率的。

**Q13.** ホストOSはどのようにして仮想マシン上の、CPU、メモリ、デバイスを制御しているか説明して欲しい。

    > （未回答）

    **模範解答**

    3資源それぞれで異なる機構が使われる。

    - **CPU**: [OS-Virtualization §1・§9](OS-Virtualization.md#isolation-protection) の**ハイパーバイザ**（ring -1）が最終的な監督者。ゲストOSは自分がring 0（カーネル）のつもりで動くが、実際には**特権命令・センシティブ命令の実行がトラップされ**ハイパーバイザに制御が渡る（[§5 Popek-Goldberg要件](OS-Virtualization.md#thrashing-popek-goldberg)）。**Intel VT-x / AMD-V** はこのトラップをハードウェアレベルで行う専用モード（ルート/非ルートモード）を提供し、ソフトウェアのバイナリトランスレーションなしに実現する。
    - **メモリ**: [§2 ネステッドページング](OS-Virtualization.md#nested-paging)。ゲスト仮想アドレス(GVA) → ゲスト物理アドレス(GPA) → ホスト物理アドレス(HPA) の**2段階変換**が必要で、ゲストが「物理アドレス」だと思っているものは実はハイパーバイザが割り当てたもう1枚の仮想アドレスにすぎない。ソフトウェアのみの**シャドウページテーブル**（ゲストのページテーブル操作を全てトラップし裏で保守、高コスト）か、ハードウェア支援の**EPT/NPT**（1回のページウォークで解決、VM exitが激減）で実現する。
    - **デバイス**: [§3 仮想デバイス](OS-Virtualization.md#virtual-fs-devices)。**フルエミュレーション**（実デバイスの挙動をソフトウェアで完全再現、互換性最大だが遅い）、**準仮想化**（`virtio` 等、ゲスト専用の軽量ドライバで高速）、**パススルー**（実デバイスの一部を直接ゲストに渡す、ほぼネイティブ速度だがライブマイグレーションが難しい）の3方式がある。
    - 実装例として [§9](OS-Virtualization.md#hypervisors) の **QEMU-KVM**: KVM（カーネルモジュール）がVT-x/AMD-Vを使いCPU・メモリ仮想化を担当し、QEMU（ユーザ空間プロセス）が仮想デバイスのエミュレーションを担当する——ポリシー/メカニズムの分離がハイパーバイザの実装にも現れている。
