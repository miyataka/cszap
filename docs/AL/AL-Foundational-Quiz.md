??? question "Q1. 動的配列は配列と何が違う?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 配列は、固定的な長さをもつ。動的配列は、配列に要素を追加するときに自動的に配列長を伸ばす機能がある。

    **模範解答**

    配列は固定長で生成時にサイズが確定する。動的配列は容量 (capacity) を内部に持ち、要素追加で容量を超えると**倍程度の新領域を確保してコピー**する。これにより末尾追加は**償却 O(1)**。要素アクセスはどちらも O(1)。

    **採点 0.8** — 方向性は正確。償却 O(1)・容量倍増の仕組みに触れられると満点。

    関連: [Q&A Q9（Go slice ＝ 動的配列で実装された List）](AL-Foundational-QA.md#q9)

??? question "Q2. 動的配列とリンクリストはどう使い分けるか?　【採点 0.5 / 1.0】"

    **本人の回答**

    > 物理メモリ上での連続的な配置をしたいときは、動的配列（シーケンシャルアクセスをしたいときなど）。物理メモリ上での位置関係を特段重視しない場合は、リンクトリスト。

    **模範解答**

    | | 動的配列 | リンクリスト |
    |---|---|---|
    | ランダムアクセス | **O(1)** | O(n) |
    | 中間の挿入・削除 | O(n)（要素ずらし） | **O(1)**（参照を持っていれば） |
    | メモリ | 連続・キャッシュ効率良 | ポインタ分のオーバーヘッド |

    添字アクセスや走査が主体なら**動的配列**、中間挿入・削除が頻繁なら**リンクリスト**。

    **採点 0.5** — 核心（ランダムアクセス O(1) vs 中間挿入削除 O(1)）が曖昧。「シーケンシャルアクセス」はリンクリストでも可能なので使い分けの論拠にならない。

??? question "Q3. 二次元配列と、配列の配列の違いは何か?　【採点 0.7 / 1.0】"

    **本人の回答**

    > 二次元配列は、二次元方向の配列のサイズが一様であるものをいう。配列の配列は、二次元方向の配列のサイズがバラバラでもよい。

    **模範解答**

    二次元配列は全行が同長（矩形）で、メモリ上は**連続した1ブロック**に格納される。配列の配列（ジャグ配列）は各行の長さが異なってよく、各行は別々に確保され**ポインタ経由で参照**される（メモリ非連続）。

    **採点 0.7** — サイズの一様/不均一は正しい。メモリ連続性 vs 間接参照に触れられると満点。

??? question "Q5. スタック、キュー、デックは動的配列／リンクリストで実装できるか?　【採点 0.5 / 1.0】"

    **本人の回答（一次）**

    > スタック: 動的配列でもリンクリストでも可能／キュー: 動的配列でもリンクリストでも可能／**デック: リンクリストでのみ実装可能**

??? question "Q6. デックがあるので、スタック・キューをコードで使うことは無い。yes か no か? 理由は?　【採点 0.6 / 1.0】"

    **本人の回答**

    **模範解答**

    **採点 0.6** — 結論は正。インターフェースの明確さ・誤用防止に触れられるとなお良い。

<a id="quiz-q7"></a>

??? question "Q7. ハッシュテーブルは挿入・削除・検索が O(1) で優れている。その理由は?　【採点 0.7 / 1.0】"

    **本人の回答（一次）**

    > シーケンシャルな走査をほぼしないから。ただしハッシュ衝突の処理の仕方によって chaining などで走査することはある。

    **本人の回答（二次・調べて）**

    > ハッシュ関数で key を、配列の添字に変換することで、配列の O(1) アクセスを利用しているため。

    **模範解答**

    ハッシュ関数で key を配列の添字に変換し、配列の O(1) ランダムアクセスを利用するため。ただし**平均** O(1) で、衝突が多いと最悪 O(n)。

    **採点 0.7** — 二次回答が核心を突いている。平均/最悪の但し書きがあれば満点。

    関連: [Q&A Q6（衝突対処）](AL-Foundational-QA.md#q6)

??? question "Q8. O(1) なので O(log n) のアルゴリズムを使うことは無い。yes か no か? 理由は?　【採点 0.3 / 1.0】"

    **本人の回答**

    > no: ハッシュは、実データサイズ以上にデータ構造として確保する領域が大きく、空間効率が悪いため。／No: 順序性や（※書きかけで途切れている）

    **模範解答**

    No。ハッシュは**順序を保持しない**ため、範囲検索・ソート列挙・最小/最大取得ができない。空間効率も悪い。順序が必要なら平衡 BST（O(log n)）を使う。

    **採点 0.3** — 空間効率は正しいが、最重要の**順序性**が書きかけで未完。

??? question "Q9. ハッシュの衝突とその解決法について説明できるか?　【採点 0.6 / 1.0】"

    **本人の回答**

    > 衝突とは、複数の値が同一ハッシュ key に割り当てられること。chaining や XXX といった解決方法がある。chaining は、同一 key の複数値を配列ですべて保持しておく方法。XXX は、衝突した場合は後続の空いている箇所をみつけ、記録する方法。

    **模範解答**

    衝突＝異なる key が同じハッシュ値（添字）に割り当たること。(1) **チェイニング**＝各バケットに連結リスト等で複数要素を保持、(2) **オープンアドレス法**＝衝突時に別の空きバケットを探索（線形探索/二次探索/ダブルハッシュ）。

    **採点 0.6** — 概念は正しく理解。「XXX」＝オープンアドレス法の正式名称が出れば加点。

    関連: [Q&A Q6（probing / chaining / rehash）](AL-Foundational-QA.md#q6)

??? question "Q10. グラフの隣接表現と行列表現の使い分けは?　【採点 0.7 / 1.0】"

    **本人の回答**

    > グラフが疎な場合、隣接表現が有利。グラフが密な場合、行列表現が有利になる。

    **模範解答**

    隣接リストは空間 O(V+E) で**疎グラフに有利**、隣接行列は空間 O(V²) だが辺の存在判定が O(1) で**密グラフに有利**。

    **採点 0.7** — 結論は正しい。空間計算量・辺判定の理由付けがあれば満点。

    関連: [Q&A Q19（疎/密の判断）](AL-Foundational-QA.md#q19)、[Q&A Q2（Graph ADT と実装別の計算量）](AL-Foundational-QA.md#q2)

??? question "Q11. 集合を表現する時、二分木とハッシュの使い分けは?　【採点 0.6 / 1.0】"

    **本人の回答**

    > ソートされていることを利用する場面があるかどうかで決める。

??? question "Q12. Set, SortedSet, MultiSet の使い分けは?　【採点 0.3 / 1.0】"

    **本人の回答**

    > 順序を保持したいときは SortedSet、保持する必要がないときは Set。MultiSet がわからない…

    **模範解答**

    - **Set**＝重複なし／順序保証なし
    - **SortedSet**＝重複なし／要素がソート順に保たれる（範囲検索・順序列挙が可能）
    - **MultiSet（バッグ）**＝**重複を許す集合**（同じ値を複数回保持し、個数を数えられる）

    **採点 0.3** — MultiSet が未回答。SortedSet の「順序」がソート順である点も曖昧。

??? question "Q13. dfs / bfs の使い分けは?　【採点 0.8 / 1.0】"

    **本人の回答**

    > DFS は Depth First Search: ある条件を満たすルートが一つ以上存在するか？というときは早い。閉路判定（ループしているかどうか）に使える。BFS は Width First Search: 最短経路をみつけたいときに使える。

??? question "Q15. ディスクの上のデータをクイックソートすると問題ありますか?　【採点 0.4 / 1.0】"

    **本人の回答**

    > 問題はある。書き戻す時間が支配的になってしまうため。

    **模範解答**

    問題あり。クイックソートは**ランダムアクセスが多く**、ディスクのシーク/ページングが頻発して非効率。外部ソートには逐次アクセス主体の**マージソート**が適する。

    **採点 0.4** — 「問題あり」は正。核心はランダムシークの多さ。「書き戻しが支配的」は方向はずれている。

??? question "Q16. クイックソートとマージソートの使い分けは?　【採点 0.0 / 1.0】"

    **本人の回答**

    > わからない。

    **模範解答**

    | | クイックソート | マージソート |
    |---|---|---|
    | 平均 | O(n log n) | O(n log n) |
    | 最悪 | O(n²) | **O(n log n)** |
    | メモリ | in-place（定数倍小） | 追加 O(n) |
    | 安定性 | 不安定 | **安定** |

    メモリ制約下の内部ソートは**クイック**、安定性が必要・連結リスト・外部ソートは**マージ**。

    **採点 0.0** — 未回答。

??? question "Q17. 挿入ソートは O(n²) で計算量的に遅い。使うべき場面は存在するのか?　【採点 0.8 / 1.0】"

    **本人の回答**

??? question "Q18. timsort はなぜ早い?　【採点 0.3 / 1.0】"

??? question "Q19. ダイクストラ法を非エンジニアにわかるよう日本語で説明してください。　【採点 0.2 / 1.0】"

    **本人の回答**

    > 向きを持たず、ループしておらず、かつ重みづけがあるグラフから、最短や最良のルートを選びだすときに使う。どのように: relaxation を行う。

    **模範解答**

    重み付きグラフで1つの出発点から各地点への最短（最小コスト）経路を求めるアルゴリズム。条件は**辺の重みが非負**であること（**有向/無向・閉路の有無は問わない**）。動作は「未確定地点のうち暫定距離が最小のものを確定し、その隣接の暫定距離を更新（緩和）」の繰り返し。非エンジニア向けには「カーナビが最短ルートを選ぶ仕組み」と例えると伝わる。

    **採点 0.2** — **適用条件が根本的に誤り**。「向きを持たず・ループしておらず」ではなく、正しい制約は**非負の重み**。また非エンジニア向け設問なのに「relaxation」という専門用語のみで説明していない。

    関連: [Q&A Q12（ダイクストラ法）](AL-Foundational-QA.md#q12)、[Q&A Q13（なぜ relax と呼ぶか）](AL-Foundational-QA.md#q13)

??? question "Q20. ダイクストラ法とワーシャルフロイド法の使い分けは?　【採点 0.0 / 1.0】"

    **本人の回答**

    > （未回答）

    **模範解答**

??? question "Q21. トポロジカルソートを非エンジニアにわかるよう日本語で説明してください。　【採点 0.4 / 1.0】"

    **本人の回答**

<a id="quiz-q23"></a>

??? question "Q23. バケツソートはなぜ早い? Pseudo とはどういう意味?　【採点 0.4 / 1.0】"

    **本人の回答**

    > 数値同士の比較をしないから。比較はしないが key 自体が範囲を絞り込む役割を担っている。

    **模範解答**

    要素を値域で区切ったバケツに分配し**比較を回避**するため、値域が限定的なら O(n+k)。ただし計算量が値域 k に依存し、入力サイズだけでは多項式時間と言えないため**擬似多項式時間（pseudo-polynomial）**と呼ばれる。

    **採点 0.4** — 「比較しない」は正しい。**Pseudo（擬似多項式）の説明が無い**。

    関連: [Q&A Q11（比較ソートの下限と、値を使うソート）](AL-Foundational-QA.md#q11)

??? question "Q24. データの追加・最小データの取得・最小データの削除を行いたいとき、どのデータ構造を選ぶ?　【採点 0.8 / 1.0】"

??? question "Q25. データの追加・データの削除・昇順のデータの列挙を行いたいとき、どのデータ構造を選ぶ?　【採点 0.8 / 1.0】"
