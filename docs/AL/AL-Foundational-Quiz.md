??? question "Q1. 動的配列は配列と何が違う?　【採点 0.7 / 1.0】"

    **本人の回答**

    > 配列は、固定サイズをもつ。動的配列は、必要になったタイミングでサイズを増やす。

    **採点 0.7** — 方向は正確。償却 O(1)・容量倍増（倍程度の新領域確保＋コピー）に触れると満点。前回(0.8)と同水準。

??? question "Q2. 動的配列とリンクリストはどう使い分けるか?　【採点 0.9 / 1.0】"

    **本人の回答**

    > 動的配列は、メモリ上での位置が並んでいるが、リンクリストはメモリの位置が隣接していることは保証されていない。N番目へのアクセスが動的配列はO(1), リンクリストはO(N). 挿入・削除に動的配列はO(N), リンクリストはO(1)

    **採点 0.9** — ランダムアクセス O(1) vs 中間挿入削除 O(1) を計算量つきで明示。前回(0.5)から大幅改善。「どちらをいつ選ぶか」の結論を一言添えれば満点。

??? question "Q3. 二次元配列と、配列の配列の違いは何か?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 二次元配列は、2次元方向の配列の長さが一律。配列の配列は一律ではないという違いがある。二次元配列はメモリ上では一列に確保される。配列の配列はそうではない。

    **採点 0.8** — 一律/非一律＋メモリ連続性を指摘。「ジャグ配列はポインタ経由の間接参照」と言えると満点。

??? question "Q4. 双方向リンクリストより単方向リンクリストの方が便利な点はあるか?　【採点 0.7 / 1.0】"

    **本人の回答**

    > 実装が単純にできる。メモリ使用量の削減

    **採点 0.7** — 正しい。「ノードあたりのポインタが1つで済む」と具体化すると掘り下げ◎。

??? question "Q5. スタック、キュー、デックは動的配列／リンクリストで実装できるか?　【採点 0.6 / 1.0】"

    **本人の回答**

    **採点 0.6** — 結論は正（前回の「デックはリンクリストのみ」誤答を克服）。デックがリングバッファで配列実装できる等の根拠があれば加点。

??? question "Q6. デックがあるので、スタック・キューをコードで使うことは無い。yes か no か? 理由は?　【採点 0.8 / 1.0】"

    **採点 0.8** — 誤用防止・意図の明確化に言及できた。

??? question "Q7. ハッシュテーブルは挿入・削除・検索が O(1) で優れている。その理由は?　【採点 0.7 / 1.0】"

    **本人の回答**

    > 内部的な配列にアクセスする際に、ハッシュを計算することで添字を特定して、ランダムアクセスできる. よって挿入・削除・検索をO(1)で実行できる

    **採点 0.7** — 核心を突く。ただし**平均** O(1)・衝突多発時は最悪 O(n) の但し書きがあれば満点。

??? question "Q8. O(1) なので O(log n) のアルゴリズムを使うことは無い。yes か no か? 理由は?　【採点 0.8 / 1.0】"

    **本人の回答**

    > No: ハッシュテーブルの弱点としては、ソートされていないこと。これによりレンジアクセスや、最小最大を取得する処理では、全要素を調べるしかない。heapや二分探索木は効率的に行える

    **採点 0.8** — 最重要の「順序を保持しない」を核心として指摘。前回(0.3・書きかけ)から大幅改善。

??? question "Q9. ハッシュの衝突とその解決法について説明できるか?　【採点 0.8 / 1.0】"

    **本人の回答**

    > ハッシュの衝突とは、ハッシュテーブルで、別の要素に同一ハッシュが割り当てられてしまうこと。解決法にはオープンアドレスとchainingのふたつがあり、オープンアドレスは衝突したら、隣の空いている箇所を探して配置する。chainingは、リンクリストとして、衝突した全要素を保持するやりかた

    **採点 0.8** — オープンアドレス法・chaining を正式名称で説明。線形/二次探索・ダブルハッシュの細分まで出れば満点。前回(0.6)から改善。

??? question "Q10. グラフの隣接表現と行列表現の使い分けは?　【採点 0.0 / 1.0】"

    **本人の回答**

    > わからない

    **採点 0.0** — 前回(0.7)は答えられていた**忘却**。隣接リスト＝空間 O(V+E)・疎グラフ向き／隣接行列＝空間 O(V²)・辺判定 O(1)・密グラフ向き。最優先で再記憶。

??? question "Q11. 集合を表現する時、二分木とハッシュの使い分けは?　【採点 0.6 / 1.0】"

    **本人の回答**

    > ソートされている状態にしたいかどうかで決まる。ソートされていると、最大・最小の取得、レンジでの取得が容易になる

    **採点 0.6** — 方向は正しい。平衡BST=O(log n)／ハッシュ=平均O(1) の計算量を添えると論拠が固まる。

??? question "Q12. Set, SortedSet, MultiSet の使い分けは?　【採点 0.6 / 1.0】"

    **本人の回答**

    > Setは順序がなく、重複排除された構造、SortedSetは、ソートされている。MultiSetは特定のキーで複数の値を保持したいときに利用できる

    **採点 0.6** — Set/SortedSet は正しい。MultiSet は「**重複を許す集合**（同じ値を複数回保持・個数を数える）」が正。「キーで複数の値」は MultiMap に近い混同。前回(0.3・未回答)から改善。

??? question "Q13. dfs / bfs の使い分けは?　【採点 0.8 / 1.0】"

    **本人の回答**

    > DFS: ある条件を満たすものが一つ以上存在するかどうかを確認するときに使う。閉路であるかどうかなど。BFS: 最短経路を判定したいときに使える。

    **採点 0.8** — 使い分けは正確。実装(stack/queue)・計算量 O(V+E)・「BFSは重みなし最短」に触れると満点。

??? question "Q14. ソートが安定しているとはどういう意味か?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 順序として等しい要素が複数ある場合、ソート前後で、相対位置が維持されるということ。

    **採点 0.8** — 「等しいキーの相対順序が保たれる」をほぼ言い切れた。前回(0.6)から改善。

??? question "Q15. ディスクの上のデータをクイックソートすると問題ありますか?　【採点 0.3 / 1.0】"

    **本人の回答**

    > 問題はある。quicksortはin-placeな処理ではないので、入出力が多いととても遅い処理になってしまう

    **採点 0.3** — 「問題あり」は正だが**「quicksort は in-place でない」は事実誤認**（quicksort は in-place）。核心は**ランダムアクセス（シーク/ページング）の多さ**。外部ソートは逐次アクセス主体のマージソートが適する。

??? question "Q16. クイックソートとマージソートの使い分けは?　【採点 0.8 / 1.0】"

    **本人の回答**

    > クイックソートは、安定ではない、平均的には早いO(N log N)が、最悪ケースではO(N^2)になる。マージソートは、安定ソートで、かつ最悪計算量はO(N log N)である。一定時間内に処理を確実に終わらせたい場合はマージソートを利用するとよい

    **採点 0.8** — 計算量・安定性・用途を的確に。**前回 0.0 → 0.8 の最大の改善**。メモリ（in-place vs 追加 O(n)）に触れれば満点。

??? question "Q17. 挿入ソートは O(n²) で計算量的に遅い。使うべき場面は存在するのか?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 存在する。要素数が少ない。20以下程度のときは、単純にループをしたほうが早いため、実務上は利用価値がある。

    **採点 0.8** — 少要素で速いのは正しい。「**ほぼ整列済みのデータ**で O(n) に近づく」にも触れると満点。

??? question "Q18. timsort はなぜ早い?　【採点 0.3 / 1.0】"

    **本人の回答**

    > 要素数の大小で、ソートアルゴリズムを使い分けるから。要素数が少ないときは、挿入ソート、多ければクイックソートを利用する

    **採点 0.3** — 本質の **run（既存の整列済み区間）の検出・活用**が欠落。timsort は run を挿入ソート＋安定マージで統合するハイブリッド（クイックソートは使わない）。前回から未改善。

??? question "Q19. ダイクストラ法を非エンジニアにわかるよう日本語で説明してください。　【採点 0.3 / 1.0】"

    **本人の回答**

    > ダイクストラ法は、重み付き無向グラフで、最短経路を探索するときに使う。

    **採点 0.3** — 前回の「向きを持たず・ループしておらず」からループ制約は消えたが、**「無向」限定が誤り**。正しい条件は**辺の重みが非負**（有向/無向・閉路は不問）。また非エンジニア向け設問なので「カーナビの最短ルート」等の比喩がほしい。

??? question "Q20. ダイクストラ法とワーシャルフロイド法の使い分けは?　【採点 0.0 / 1.0】"

??? question "Q1. 動的配列は配列と何が違う?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 配列は、固定的な長さをもつ。動的配列は、配列に要素を追加するときに自動的に配列長を伸ばす機能がある。

    **模範解答**

    配列は固定長で生成時にサイズが確定する。動的配列は容量 (capacity) を内部に持ち、要素追加で容量を超えると**倍程度の新領域を確保してコピー**する。これにより末尾追加は**償却 O(1)**。要素アクセスはどちらも O(1)。

    **採点 0.8** — 方向性は正確。償却 O(1)・容量倍増の仕組みに触れられると満点。

    関連: [Q&A Q9（Go slice ＝ 動的配列で実装された List）](AL-Foundational-QA.md#q9)

??? question "Q2. 動的配列とリンクリストはどう使い分けるか?　【採点 0.5 / 1.0】"

    **本人の回答**

    > 物理メモリ上での連続的な配置をしたいときは、動的配列（シーケンシャルアクセスをしたいときなど）。物理メモリ上での位置関係を特段重視しない場合は、リンクトリスト。

    **模範解答**

    | | 動的配列 | リンクリスト |
    |---|---|---|
    | ランダムアクセス | **O(1)** | O(n) |
    | 中間の挿入・削除 | O(n)（要素ずらし） | **O(1)**（参照を持っていれば） |
    | メモリ | 連続・キャッシュ効率良 | ポインタ分のオーバーヘッド |

    添字アクセスや走査が主体なら**動的配列**、中間挿入・削除が頻繁なら**リンクリスト**。

    **採点 0.5** — 核心（ランダムアクセス O(1) vs 中間挿入削除 O(1)）が曖昧。「シーケンシャルアクセス」はリンクリストでも可能なので使い分けの論拠にならない。

??? question "Q3. 二次元配列と、配列の配列の違いは何か?　【採点 0.7 / 1.0】"

    **本人の回答**

    > 二次元配列は、二次元方向の配列のサイズが一様であるものをいう。配列の配列は、二次元方向の配列のサイズがバラバラでもよい。

    **模範解答**

    二次元配列は全行が同長（矩形）で、メモリ上は**連続した1ブロック**に格納される。配列の配列（ジャグ配列）は各行の長さが異なってよく、各行は別々に確保され**ポインタ経由で参照**される（メモリ非連続）。

    **採点 0.7** — サイズの一様/不均一は正しい。メモリ連続性 vs 間接参照に触れられると満点。

??? question "Q19. ダイクストラ法を非エンジニアにわかるよう日本語で説明してください。　【採点 0.2 / 1.0】"

    **本人の回答**

    > 向きを持たず、ループしておらず、かつ重みづけがあるグラフから、最短や最良のルートを選びだすときに使う。どのように: relaxation を行う。

    **模範解答**

    重み付きグラフで1つの出発点から各地点への最短（最小コスト）経路を求めるアルゴリズム。条件は**辺の重みが非負**であること（**有向/無向・閉路の有無は問わない**）。動作は「未確定地点のうち暫定距離が最小のものを確定し、その隣接の暫定距離を更新（緩和）」の繰り返し。非エンジニア向けには「カーナビが最短ルートを選ぶ仕組み」と例えると伝わる。

    **採点 0.2** — **適用条件が根本的に誤り**。「向きを持たず・ループしておらず」ではなく、正しい制約は**非負の重み**。また非エンジニア向け設問なのに「relaxation」という専門用語のみで説明していない。

    関連: [Q&A Q12（ダイクストラ法）](AL-Foundational-QA.md#q12)、[Q&A Q13（なぜ relax と呼ぶか）](AL-Foundational-QA.md#q13)

??? question "Q21. トポロジカルソートを非エンジニアにわかるよう日本語で説明してください。　【採点 0.4 / 1.0】"

    **本人の回答**

    > 向きをもつ、ループしていないグラフを、矢印の向きに沿って並べ替えることができる。どのように: TODO。

    **模範解答**

    有向非巡回グラフ（DAG）の頂点を、**すべての矢印が前→後ろ**になるよう一列に並べる。動作は「入次数0の頂点から順に取り出す（Kahn 法）」か「DFS の帰りがけ順の逆」。例＝履修の前提科目順、ビルドの依存解決。

    **採点 0.4** — 「何のため」の前半は正しい。「どのように」が TODO で未完。

    関連: [Q&A Q3（DAG と閉路）](AL-Foundational-QA.md#q3)、[Q&A Q15（DFS）](AL-Foundational-QA.md#q15)

??? question "Q22. トポロジカルソートが失敗するケースはありますか?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 閉路（ループ）が存在するとき、順序づけができずに失敗する。

    **模範解答**

    **閉路（循環依存）が存在するとき**。一方向に並べられず失敗する（＝ DAG でないと不可能）。

    **採点 0.8** — 正しい。簡潔。

    関連: [Q&A Q3（閉路と DAG）](AL-Foundational-QA.md#q3)

<a id="quiz-q23"></a>

??? question "Q23. バケツソートはなぜ早い? Pseudo とはどういう意味?　【採点 0.4 / 1.0】"

    **本人の回答**

    > 数値同士の比較をしないから。比較はしないが key 自体が範囲を絞り込む役割を担っている。

    **模範解答**

    要素を値域で区切ったバケツに分配し**比較を回避**するため、値域が限定的なら O(n+k)。ただし計算量が値域 k に依存し、入力サイズだけでは多項式時間と言えないため**擬似多項式時間（pseudo-polynomial）**と呼ばれる。

    **採点 0.4** — 「比較しない」は正しい。**Pseudo（擬似多項式）の説明が無い**。

    関連: [Q&A Q11（比較ソートの下限と、値を使うソート）](AL-Foundational-QA.md#q11)

<a id="quiz-q24"></a>

??? question "Q24. データの追加・最小データの取得・最小データの削除を行いたいとき、どのデータ構造を選ぶ?　【採点 0.8 / 1.0】"

    **本人の回答**

    > ヒープ。全要素をソートした状態に保つ必要がないので、効率がよい。

    **模範解答**

    **ヒープ（優先度付きキュー）**。最小取得 O(1)、追加/削除 O(log n)。全体をソートする必要がないので効率的。

    **採点 0.8** — 正しい。計算量に触れられると満点。

<a id="quiz-q25"></a>

??? question "Q25. データの追加・データの削除・昇順のデータの列挙を行いたいとき、どのデータ構造を選ぶ?　【採点 0.8 / 1.0】"

    **本人の回答**

    > 二分探索木。常にソートされた状態を保つのであればこれがよいと思う。

    **模範解答**

    **平衡二分探索木**（AVL/赤黒木）。追加/削除/検索 O(log n)、中順走査で昇順列挙 O(n)。

    **採点 0.8** — 正しい。「平衡」である必要性に触れられると満点（非平衡だと最悪 O(n)）。

<a id="quiz-q26"></a>

??? question "Q26. データの追加・データの削除・データの挿入順での列挙を行いたいとき、どういうデータ構造があればよい?　【採点 0.7 / 1.0】"

    **本人の回答**

    > ADT としてはキュー。具体的なデータ構造としては単方向リンクトリストがあればよい。

    **模範解答**

    **挿入順を保持するリスト**。FIFO 取り出しならキュー、任意位置の削除があるなら（双方向）リンクリスト。

    **採点 0.7** — 妥当。ただし「キュー」だと先頭からしか取り出せず、任意位置削除とは相性が微妙。
