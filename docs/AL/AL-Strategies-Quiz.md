<a id="quiz-q1"></a>

??? question "Q1. サイズ n の配列 A で、i<j かつ A[i]>A[j] を満たすペア数を、総当たりで求めるアルゴリズム（逆転数 inversions）　【採点 0.4 / 1.0】"

    **本人の回答**

    ```go
    func unsortedParts(nums []int) int {
        count := 0
        for i:=0; i<len(nums)-1; i++ {
            for j := i+1; j<len(nums); j++ {
                if nums[i] > nums[j] {
                    count++
                    break
                }
            }
        }
        return count
    }
    ```

    **模範解答**

    全ペア `(i,j)`（`i<j`）を二重ループで走査し、`A[i] > A[j]` のたびに数える。**`break` を入れてはいけない**——入れると各 i につき最大1しか数えず、「後ろに自分より小さい要素を1つ以上持つ i の数」になってしまう（求めたい**逆転ペア数**ではない）。計算量は **O(n²)**。

    ```go
    func countInversions(nums []int) int {
        count := 0
        for i := 0; i < len(nums)-1; i++ {
            for j := i + 1; j < len(nums); j++ {
                if nums[i] > nums[j] {
                    count++ // break しない
                }
            }
        }
        return count
    }
    ```

    **採点 0.4** — 二重ループ O(n²) の骨格は正しいが、`break` による**数え落とし**が致命的。問題が要求するのは「ペアの個数」。O(n²) の明記も無い。

<a id="quiz-q2"></a>

??? question "Q2. 上記（逆転数）を分割統治で求めるアルゴリズム　【採点 0.5 / 1.0】"

    **本人の回答**

    > 配列を繰り返し半分に分け、その領域での `A[i] > A[j]` となる個数を数え上げていく方法。最初は前半分と後ろ半分に分け、その次は前半分をさらに分割し、最後に要素が2〜（記述途中）

    **模範解答**

    **マージソートに数え上げを組み込む**手法。配列を半分に分け、(1)左側内の逆転数、(2)右側内の逆転数、(3)**左右をまたぐ逆転数**を足す。(3) はマージ時、右の要素 `A[j]` を先に取り出すたびに「左に残っている要素数」だけ逆転が確定するので、マージのついでに O(n) で数えられる。全体は **O(n log n)**（総当たり O(n²) からの改善）。これは[分割統治（AL-Strategies §3）](AL-Strategies.md)の典型例。

    **採点 0.5** — 「半分に分けて数える」という方向は正しいが、**核心＝マージ時に跨ぐペアを O(n) で数える**部分が無く、記述も途中で切れている。O(n log n) への言及も欲しい。

<a id="quiz-q3"></a>

??? question "Q3. 貪欲法とはどういう手法か　【採点 0.7 / 1.0】"

    **本人の回答**

    > そのときの（局所）最適解をとり続ける手法。そのときの最大ポイント、次のノードまでの最短ルートなどを取り続ける。

    **模範解答**

    各ステップで**その時点で最善に見える選択**を行い、**一度選んだら後戻りしない**手法。実装が単純で高速だが、**局所的な最善が全体最善になる保証はない**（保証できる問題でのみ最適。例: ダイクストラ、クラスカル）。

    **採点 0.7** — 「局所最適を取り続ける」は核心を突く。「後戻りしない」「最適性は問題次第」に触れると満点。

    関連: [AL-Strategies-QA Q9（貪欲法の3例: Dijkstra/Kruskal/Knapsack）](AL-Strategies-QA.md#q9)

<a id="quiz-q4"></a>

??? question "Q4. 貪欲法で最適解が求まらないのはどういう問題か　【採点 0.6 / 1.0】"

    **本人の回答**

    > 局所最適と大域最適が異なる問題。ある部分での最適解が、全体でみると異なる場合。

    **模範解答**

    **局所最適の連鎖が大域最適に一致しない問題**。代表例は **0/1 ナップサック**（単価が高い品を貪欲に詰めても最適にならない）や、特定硬貨体系での両替問題。貪欲が最適になるには「最適部分構造＋貪欲選択性」が必要。

    **採点 0.6** — 「局所≠大域」は正しいが抽象的。具体例を1つ挙げると論拠が固まる。

    関連: [AL-Strategies-QA Q3（ナップサック問題）](AL-Strategies-QA.md#q3)

<a id="quiz-q5"></a>

??? question "Q5. 逐次改善法（iterative improvement）で最適解が求まらないのはどういう問題か　【採点 0.6 / 1.0】"

    **本人の回答**

    > 局所最適と大域最適が異なる問題。ある部分での最適解が、全体でみると異なる場合。

    **模範解答**

    逐次改善法（山登り法など）は「現状から少し改善する方向へ動く」ため、**局所最適 (local optimum) に到達するとそこから抜け出せず、大域最適に届かない**問題で失敗する（多峰性の地形）。回避策に焼きなまし法・多スタート・乱択がある。

    **採点 0.6** — Q4 と同文だが、逐次改善法での核心は「**局所最適に捕まる**」という*停留*の現象。用語（局所最適）と「抜け出せない」を明示したい。

    関連: [AL-Strategies-QA Q22（反復改善法）](AL-Strategies-QA.md#q22)

<a id="quiz-q6"></a>

??? question "Q6. 分割統治法とはどういう手法か、例を一つ　【採点 0.7 / 1.0】"

    **本人の回答**

    > 問題を小さく繰り返し分割して、小さな部分から再帰的な処理を行う手法。例としてはマージソート。

    **模範解答**

    問題を**同種の小問題に分割 (divide)** → **再帰的に解く (conquer)** → **結果を結合 (combine)** する手法。マージソート（分割→各半分をソート→**マージで結合**）、クイックソート、二分探索、Strassen 法など。多くは漸化式 `T(n)=aT(n/b)+f(n)` で解析できる。

    **採点 0.7** — 分割と再帰は正しい。**結合 (combine) ステップ**と計算量（例: マージソート O(n log n)）に触れると満点。

    関連: [AL-Strategies-QA Q7（クイックソート）](AL-Strategies-QA.md#q7)、[AL-Strategies-QA Q8（Strassen 法）](AL-Strategies-QA.md#q8)

<a id="quiz-q7"></a>

??? question "Q7. 分枝限定法（branch-and-bound）について　【採点 0.7 / 1.0】"

    **本人の回答**

    > これまでに探索した部分での最適解と比較することで、ある程度の処理で切り上げる（分岐を枝刈りする）手法。

    **模範解答**

    探索空間を木に**分枝 (branch)** しつつ、各部分問題の**限定 (bound)＝到達しうる最良値の見積り（上界/下界）**を計算し、「現在の暫定最適を超えられない枝」を**枝刈り**する手法。最悪は全探索だが、良い限定関数で実用上は大幅に削減できる。

    **採点 0.7** — 「暫定最適と比較して枝刈り」は正しい。**限定＝上下界の見積り**という用語まで出せると満点。

    関連: [AL-Strategies-QA Q19（分枝限定法）](AL-Strategies-QA.md#q19)

<a id="quiz-q8"></a>

??? question "Q8. 計算時間と空間がトレードオフになるアルゴリズムを1つ挙げ、どう調整するか　【採点 0.8 / 1.0】"

    **本人の回答**

    > ハッシュテーブルは探索・挿入・削除が O(1) となる代わりに、衝突率を下げるため実際の要素より広めの空間が必要。格納要素数が一定割合を超えるとリハッシュ（より大きい配列を確保して再配置）するコストが発生する。

    **模範解答**

    **ハッシュ表**（または**メモ化／DP**）。ハッシュ表は**負荷率 (load factor) α＝要素数/バケット数**を小さく保つほど衝突が減り平均 O(1) に近づくが、空間を多く使う。α が閾値を超えるとリハッシュで拡張する——**空間を多く割けば時間が速くなる**典型。メモ化も「表に答えを貯める空間」と引き換えに再計算時間を消す（→ Day3 Q3 のフィボナッチ）。

    **採点 0.8** — 負荷率・リハッシュまで具体的で良い。「α を調整軸として時間⇄空間を振る」と一言まとめると満点。

    関連: [AL-Complexity §5（時間と空間のトレードオフ）](AL-Complexity.md)、[AL-Foundational-QA Q6（衝突対処）](AL-Foundational-QA.md#q6)

??? question "Q10. 計算時間と正解確率がトレードオフになるアルゴリズムを1つ挙げ、どう調整するか　【採点 0.0 / 1.0】"

<a id="quiz-q11"></a>

??? question "Q11. すべての再帰処理がループで書けることを説明　【採点 0.4 / 1.0】"

    **本人の回答**

    > 再帰処理とループはどちらも同じロジックを繰り返し適用する手法。再帰は引数を変化させながら関数を呼び出し、入れ子で表現している。同じ処理をループで表すには、引数を変化させる処理をループの変化式に対応させればよい。

    **模範解答**

    **末尾再帰**なら引数の更新をループ変数の更新に置き換えるだけで等価になる。だが一般の再帰（分岐再帰・呼び出し後に処理が残る場合）は、**呼び出し履歴を明示的なスタックに積んで管理する**ことで反復に変換できる——CPU の**コールスタック**が自動でしている仕事を手動のスタックで再現する、というのが本質。

    **採点 0.4** — 「引数の変化＝ループ変数」は末尾再帰の直感止まり。一般の再帰を変換する核心の**明示スタック**が欠落。

    関連: [AL-Strategies-QA Q25（末尾再帰最適化）](AL-Strategies-QA.md#q25)

<a id="quiz-q12"></a>

??? question "Q12. 実務で巡回セールスマン問題に当たったら、どうアプローチするか　【採点 0.7 / 1.0】"

    **本人の回答**

    > まず要件確認から。どの程度の精度が必要か、時間的制約は何か、どんな業務で使うか、入力サイズはどうか。サイズが十分小さければ総当たりでも可能。どのような近似アルゴリズムが実用的かを調査して提案する。

    **模範解答**

    ① **要件確認**（必要な精度・許容時間・入力規模）。② 入力が小さければ**厳密解**（DP の Held–Karp は O(2ⁿ n²)、分枝限定）。③ 大きければ**近似/ヒューリスティック**（最近傍→2-opt/3-opt、Christofides、または LKH・OR-Tools 等の実装の利用）。TSP は NP困難なので「最適を諦めて要件を満たす近似」が現実解。

    **採点 0.7** — 要件確認→入力サイズで分岐→近似調査、という実務の筋は良い。具体的な手法名（Held–Karp / 2-opt / Christofides）を挙げると満点。

    関連: [AL-Strategies-QA Q2（TSP）](AL-Strategies-QA.md#q2)、[Day3 Q10（NP完全への対処）](AL-Complexity-Quiz.md#quiz-q10)
