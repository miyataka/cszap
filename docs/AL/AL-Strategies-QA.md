??? question "Q1. selection sort ってどんなアルゴリズム？"

    *(2026-06-13)*

    **A.** **「未整列部分から最小値を選んで（select）、未整列部分の先頭と交換する」を繰り返す**ソート。左側に整列済みゾーンが1要素ずつ育っていく。

    ```
    [ 29, 10, 14, 37, 13 ]   全体から最小 10 を選び、先頭 29 と交換
    [ 10 | 14, 29, 37, 13 ]  残りから最小 13 を選び、14 と交換
    [ 10, 13 | 29, 37, 14 ]  残りから最小 14 を選び、29 と交換
    [ 10, 13, 14 | 37, 29 ]  残りから最小 29 を選び、37 と交換
    [ 10, 13, 14, 29 | 37 ]  残り1個 → 完了（`|` の左が整列済み）
    ```

    ```python
    def selection_sort(a):
        n = len(a)
        for i in range(n - 1):        # 整列済みゾーンの境界
            m = i
            for j in range(i + 1, n): # 未整列部分を全スキャンして最小を探す
                if a[j] < a[m]:
                    m = j
            a[i], a[m] = a[m], a[i]   # パスごとに交換は1回だけ
        return a
    ```

    ### 性質

    | 観点 | 値 | 補足 |
    |---|---|---|
    | 比較回数 | **常に n(n−1)/2 = O(n²)** | 最小値を知るには残り全部を見るしかない。**best = worst**（整列済み入力でも O(n²)）|
    | 交換回数 | **最大 n−1 回 = O(n)** | パスごとに1回だけ。**書き込みが極端に少ない**のが唯一の取り柄（フラッシュメモリ等、書き込みコストが高い環境で現役）|
    | 追加メモリ | O(1)（in-place）| |
    | 安定性 | **不安定** | 例: `[2a, 2b, 1]` → 最小 1 と 2a を交換 → `[1, 2b, 2a]` で 2a が 2b を追い越す |

    ### パラダイム視点：なぜ Brute-Force の例なのか

    CS2023 は selection sort を [Brute-Force](AL-Strategies.md#1-brute-force) の例に挙げる。「最小値を**未整列部分の総当たりスキャン**で探す」という、定義に忠実な構えだから。

    対照的に**挿入ソートは [Decrease-and-Conquer (by a constant)](AL-Strategies.md#2-decrease-and-conquer)** の例。同じ O(n²) ソートでも構えが違う：

    | | 選択ソート（Brute-Force）| 挿入ソート（Decrease-and-Conquer）|
    |---|---|---|
    | 構え | 未整列側を**全部見て選び**、整列側の末尾に**置く** | 「n−1 個整列済みなら残り1個を**挿す**だけ」と縮小 |
    | 比較回数 | 常に O(n²) | 最悪 O(n²)、**整列済みなら O(n)** |
    | 交換/移動 | 交換 O(n) 回と少ない | 移動は最悪 O(n²) |

    **構え方（パラダイム）の違いが、入力の性質への感度の違いとして現れる**好例。「ほぼ整列済み」と分かっているなら挿入ソート、書き込み回数を抑えたいなら選択ソート、という使い分けにつながる。

    関連: [Brute-Force / 力まかせ法](AL-Strategies.md#1-brute-force)、[Decrease-and-Conquer / 減治法](AL-Strategies.md#2-decrease-and-conquer)、[AL-Foundational §5 ソート](AL-Foundational.md#5-sort)

??? question "Q2. traveling salesperson（巡回セールスパーソン問題）について教えて"

    *(2026-06-13)*

    **A.** n 個の都市と都市間の距離が与えられたとき、**全都市をちょうど1回ずつ訪れて出発地に戻る巡回路**（ハミルトン閉路）のうち、総距離最小のものを求める最適化問題。**TSP** と略す。

    ### なぜ難しいか

    出発点と向きを同一視しても巡回路は **(n−1)!/2 通り**。n=10 で約18万、n=20 で約 6×10¹⁶ 通りと爆発する。判定版（「長さ ≤ k の巡回路はあるか」）は **NP完全**、最適化版は **NP困難**（→ AL-Complexity で再登場）。

    ### このユニットでの役どころ：パラダイムのショーケース

    CS2023 が TSP を Brute-Force の例に挙げるのは入口にすぎない。**同じ問題にほぼ全パラダイムを当てられる**のが TSP の教材価値。

    | パラダイム | TSP へのアプローチ | 結果 |
    |---|---|---|
    | [Brute-Force](AL-Strategies.md#1-brute-force) | 全順列を試す | O(n!)。n≤10 程度が限界 |
    | [DP（Held-Karp）](AL-Strategies.md#5d-dynamic-programming) | 「訪問済み集合 S＋現在地 v」を状態に表を埋める | **O(n²·2ⁿ)**。n! よりずっと良いがまだ指数。空間 O(n·2ⁿ) を払って時間を買う |
    | [Greedy（最近傍法）](AL-Strategies.md#4-greedy) | 今いる都市から最も近い未訪問都市へ | 高速だが**最適保証なし**（ヒューリスティックとしての貪欲） |
    | [Branch-and-bound](AL-Strategies.md#7-handling-exponential-growth) | 部分経路から下界 (bound) を見積もり枝刈り | **厳密解**。中規模まで実用的 |
    | 近似（→ §9）| Christofides 法（距離が三角不等式を満たす metric TSP）| **最適の 1.5 倍以内**を保証 |
    | 反復改善（→ §9）| 2-opt（辺2本を付け替えて交差をほどく）、Lin-Kernighan | 実務で強力な局所探索 |

    「厳密解が要るか・入力はどの規模か・距離に三角不等式はあるか」という**問題側の条件**で、どのパラダイムに降りるかが決まる——[選択の思考フロー](AL-Strategies.md#paradigm-selection)の実演になっている。

    ### 実世界の姿

    配送ルート最適化、基板の穴あけ順序、巡回点検・検針ルートなど。現実には数千都市規模を 2-opt 系の局所探索＋メタヒューリスティクスで「ほぼ最適」に解いている。

    関連: [指数爆発への対処](AL-Strategies.md#7-handling-exponential-growth)、[Q3 knapsack](#q3)（同じく NP困難の看板問題）

??? question "Q3. knapsack（ナップサック問題）について教えて"

    *(2026-06-13)*

    **A.** 容量 W のナップサックと n 個の品物（各々に重さ wᵢ と価値 vᵢ）が与えられたとき、**容量を超えずに価値の合計を最大にする**品物の選び方を求める最適化問題。

    ### 2つの変種が決定的に違う

    | 変種 | ルール | 最適解の求め方 |
    |---|---|---|
    | **Fractional**（分割可） | 品物を途中で切って一部だけ入れてよい | **貪欲法で最適**：価値密度 vᵢ/wᵢ の高い順に詰める（交換論法で証明できる） |
    | **0/1**（分割不可） | 入れる/入れないの2択 | 貪欲は最適を外す。解空間 2ⁿ、判定版は NP完全 |

    ### 0/1 で貪欲が失敗する具体例（容量 W=10）

    | 品物 | 重さ | 価値 | 密度 |
    |---|---|---|---|
    | A | 6 | 48 | 8.0 |
    | B | 5 | 35 | 7.0 |
    | C | 5 | 35 | 7.0 |

    貪欲は密度最大の A を取る → 残り容量 4 に B も C も入らず**価値 48**。最適は **B＋C＝70**。「局所最適（密度）の積み重ねが大域最適にならない」教科書例で、[まとめページの warning](AL-Strategies.md#4-greedy) の実物がこれ。

    ### パラダイム別アプローチ

    - [Brute-Force](AL-Strategies.md#1-brute-force): 全部分集合を試す O(2ⁿ)。
    - [DP](AL-Strategies.md#5d-dynamic-programming): 「**i 番目までの品物で容量 j のときの最大価値** dp[i][j]」という表を埋めて **O(nW)**。「i 番目まで・状態 j」と言語化できる典型 DP。
    - [Branch-and-bound](AL-Strategies.md#7-handling-exponential-growth): fractional 版（貪欲で瞬時に解ける）の値を**上界 (bound)** に使って枝刈り——「緩和した問題の解を bound に使う」定石の代表例。
    - 近似（→ §9）: 任意精度の近似が多項式時間でできる **FPTAS** が存在する。

    !!! note "O(nW) は多項式じゃないの？（擬多項式時間）"
        W は「数値の大きさ」であり、入力としての W の**表記長は log W ビット**。O(nW) = O(n·2^(log W)) なので入力長に対しては指数——これを**擬多項式時間**と呼ぶ。だから「DP で解ける」ことと「NP完全」は矛盾しない（W が小さい実用例では DP が完勝する）。詳細は AL-Complexity で回収。

    関連: [Greedy / 貪欲法](AL-Strategies.md#4-greedy)、[Q2 TSP](#q2)（同じく NP困難の看板問題。TSP は「順序」、knapsack は「選択」の組合せ爆発）

??? question "Q4. insertion sort（挿入ソート）について教えて"

    *(2026-06-13)*

    **A.** **「左側を整列済みに保ち、次の要素を整列済み部分の正しい位置に挿し込む」を繰り返す**ソート。トランプの手札を並べる動きそのもの。

    ```
    [ 5 | 2, 4, 6, 1, 3 ]   2 を取り、5 の前に挿す
    [ 2, 5 | 4, 6, 1, 3 ]   4 を取り、2 と 5 の間に挿す
    [ 2, 4, 5 | 6, 1, 3 ]   6 はそのまま（すでに正しい位置）
    [ 2, 4, 5, 6 | 1, 3 ]   1 を先頭まで運んで挿す
    [ 1, 2, 4, 5, 6 | 3 ]   3 を 2 と 4 の間に挿す
    [ 1, 2, 3, 4, 5, 6 ]    完了（`|` の左が整列済み）
    ```

    ```python
    def insertion_sort(a):
        for i in range(1, len(a)):
            x = a[i]                      # 挿す要素を取り出す
            j = i - 1
            while j >= 0 and a[j] > x:    # x より大きい要素を右へずらす
                a[j + 1] = a[j]
                j -= 1
            a[j + 1] = x                  # 空いた場所に挿す
        return a
    ```

    ### 性質

    | 観点 | 値 | 補足 |
    |---|---|---|
    | 最悪・平均 | O(n²) | 逆順入力が最悪（毎回先頭まで運ぶ）|
    | **最良** | **O(n)** | **整列済み入力**なら各要素が比較1回で確定。逆転ペア数 k に対して O(n + k) |
    | 安定性 | **安定** | 同値要素を追い越さない |
    | 追加メモリ | O(1)（in-place）| |
    | その他 | **オンライン** | 要素が届くたびに挿せる（全部揃うのを待たなくてよい）|

    ### パラダイム視点：Decrease-and-Conquer (by a constant) の代表例

    「**先頭 n−1 個が整列済み**という一回り小さい解があれば、**1要素を挿すだけ**で n 個の解に拡張できる」という縮小の構え。[selection sort（Brute-Force、→ Q1）](#q1)との対比がこのユニットの核心で、似た O(n²) ソートでも**構えの違いが「ほぼ整列済み入力で O(n) に化ける」感度の差**として現れる。

    ### 実務での生存理由

    小さい配列では定数倍が軽く最速クラス。**Timsort（Python/Java 標準）や多くの quicksort 実装は、小区間（十数要素）になると挿入ソートに切り替える**。「O(n²) だから不要」ではなく「小さい n・ほぼ整列済みに最強」と使いどころが明確な例。

    ??? note "補足：挿入位置を二分探索にしたら速くなる？（binary insertion sort）"
        挿入**位置の発見**は二分探索で O(log n) にできるが、挿入のための**要素の右ずらしが O(n)** のまま残るので全体は O(n²) から変わらない。「ボトルネックは比較ではなく移動」という計算量分析の練習問題として良い。

    関連: [Decrease-and-Conquer / 減治法](AL-Strategies.md#2-decrease-and-conquer)、[Q1 selection sort](#q1)、[AL-Foundational §5 ソート](AL-Foundational.md#5-sort)

??? question "Q5. topological sort（トポロジカルソート）について教えて"

    *(2026-06-13)*

    **A.** **DAG（有向非巡回グラフ）の頂点を「すべての辺 u→v について u が v より先に来る」ように一列に並べる**アルゴリズム。「**依存関係を壊さない実行順序を作る**」と言い換えられる。

    ```mermaid
    graph LR
      下着 --> ズボン --> ベルト
      シャツ --> ベルト --> ジャケット
      シャツ --> ネクタイ --> ジャケット
    ```

    有効な並びの一例: 下着 → シャツ → ズボン → ネクタイ → ベルト → ジャケット。**順序は一意とは限らない**（シャツと下着はどちらが先でもよい）。

    ### 代表的な2つのやり方（どちらも O(V+E)）

    | 方法 | 手順 | 特徴 |
    |---|---|---|
    | **Kahn 法** | ①入次数 0 の頂点をキューへ ②取り出して出力し、出る辺を消す ③新たに入次数 0 になった頂点をキューへ、を繰り返す | 直感的。BFS 的に層が見える |
    | **DFS 帰りがけ順の逆** | DFS で「これ以上進めず戻る瞬間」に頂点をスタックへ積み、最後に逆順で読む | 実装が短い。AL-Foundational の DFS の応用 |

    ### パラダイム視点：Decrease-and-Conquer (by a constant) の例

    CS2023 がこのユニットで挙げるのは、Kahn 法が減治法の好例だから。

    - **DAG なら入次数 0 の頂点が必ず存在する**（なければ辿り続けて閉路ができてしまう）
    - それを**1個取り除くと、残りも DAG**＝一回り小さい同じ問題

    「端から確定できる要素が常にある → 1つずつ剥がす」という、[挿入ソート（→ Q4）](#q4)と同じ型。データは違えど構えは同じ、と気づくのがこのユニットの読み方。

    ### 閉路があるとどうなる？ → サイクル検出

    入次数 0 の頂点が尽き、**全頂点を出力できずに止まる**。これがそのまま**閉路検出**になる——パッケージマネージャの「循環依存エラー」の正体。「トポロジカルソートが完走できる ⇔ グラフが DAG」。

    ### 実世界の姿

    `make`・CI のビルド順序、パッケージマネージャの依存解決（npm, apt）、講義の履修順、スプレッドシートのセル再計算順、タスクスケジューリング。

    関連: [Decrease-and-Conquer / 減治法](AL-Strategies.md#2-decrease-and-conquer)、[AL-Foundational §6 グラフアルゴリズム](AL-Foundational.md#6-graph-algorithms)、[Q4 insertion sort](#q4)（同じ「1つずつ剥がす」構え）

??? question "Q6. Euclid's（ユークリッドの互除法）について教えて"

    *(2026-06-13)*

    **A.** **2つの非負整数の最大公約数 (GCD: greatest common divisor) を求める**アルゴリズム。紀元前300年頃のユークリッド『原論』に載っている、**記録に残る最古のアルゴリズム**。核心は1行：

    > **gcd(m, n) = gcd(n, m mod n)**、底は **gcd(m, 0) = m**

    ```
    gcd(48, 18)
    = gcd(18, 48 mod 18) = gcd(18, 12)
    = gcd(12, 18 mod 12) = gcd(12, 6)
    = gcd(6, 12 mod 6)   = gcd(6, 0)
    = 6
    ```

    ```python
    def gcd(m, n):
        while n:
            m, n = n, m % n
        return m
    ```

    ### なぜ正しいか

    m = qn + r（r = m mod n）と書くと、n と r の両方を割り切る数は m = qn + r も割り切り、逆に m と n を割り切る数は r = m − qn も割り切る。つまり **(m, n) の公約数の集合 = (n, r) の公約数の集合**。集合ごと同じなので最大値（GCD）も同じ。

    ### パラダイム視点：Decrease-and-Conquer (by a variable size) の代表例

    これで[減治法の3変種](AL-Strategies.md#2-decrease-and-conquer)が役者付きで揃う：

    | 縮小のしかた | 例 | 1ステップで問題は |
    |---|---|---|
    | by a constant | 挿入ソート（→ [Q4](#q4)）・トポロジカルソート（→ [Q5](#q5)） | 1 だけ減る |
    | by a constant factor | 二分探索 | 半分になる |
    | **by a variable size** | **互除法** | **m mod n だけ減る（減り幅が入力依存）** |

    ### 「可変」なのに速い：O(log min(m, n))

    **m mod n < m/2 が常に成り立つ**（n ≤ m/2 なら余りは n 未満 ≤ m/2、n > m/2 なら余りは m − n < m/2）。よって2ステップごとに必ず半分以下になり、対数時間。

    ??? note "補足：最悪ケースはフィボナッチ数（ラメの定理）"
        商が毎回 1 にしかならない＝減りが最小になるのは、**隣り合うフィボナッチ数のペア**（例: gcd(34, 21) → gcd(21, 13) → gcd(13, 8) → …）。「ステップ数が k 以上になる最小の入力は Fₖ₊₂, Fₖ₊₁」という形で正確に特徴づけられる（Lamé, 1844 — 計算量解析の最初期の成果）。

    ### 実世界の姿

    分数の約分、`lcm(m, n) = m·n / gcd(m, n)`（[問題の帰着](AL-Strategies.md#5c-problem-reduction)の例として本編にも登場）、そして**拡張ユークリッド互除法** → モジュラ逆元 → **RSA 暗号の鍵生成**。2300年前のアルゴリズムが毎日の HTTPS を支えている。

    関連: [Decrease-and-Conquer / 減治法](AL-Strategies.md#2-decrease-and-conquer)、[Q4 insertion sort](#q4)、[Q5 topological sort](#q5)（3変種の比較）

??? question "Q7. quicksort（クイックソート）について教えて"

    *(2026-06-13)*

    **A.** **「ピボット（基準値）を1つ選び、配列を『ピボット未満 / 以上』に振り分けて（partition）、左右をそれぞれ再帰的にソートする」**アルゴリズム。

    ```
    [ 3, 8, 2, 5, 1, 4, 7 ]   ピボット = 5 を選ぶ
    [ 3, 2, 1, 4 ] 5 [ 8, 7 ]  5未満を左、5以上を右へ（partition）
    ↓ 左右をそれぞれ再帰的に quicksort
    [ 1, 2, 3, 4 ] 5 [ 7, 8 ]
    → 連結は不要。partition の時点でピボットの最終位置は確定している
    ```

    ```python
    def quicksort(a, lo=0, hi=None):
        if hi is None:
            hi = len(a) - 1
        if lo >= hi:
            return a
        p = partition(a, lo, hi)   # ピボットの最終位置が決まる
        quicksort(a, lo, p - 1)    # 左半分
        quicksort(a, p + 1, hi)    # 右半分
        return a
    ```

    ### パラダイム視点：mergesort と「仕事の置き場」が逆

    どちらも [Divide-and-Conquer](AL-Strategies.md#3-divide-and-conquer) だが、対で覚えると構造が立体的になる：

    | | quicksort | mergesort |
    |---|---|---|
    | 分割 (divide) | **ここが本体**（partition で大小に振り分け） | 単純に真ん中で割るだけ |
    | 併合 (combine) | **不要**（場所が既に正しい） | **ここが本体**（2列を併合） |
    | 最悪計算量 | **O(n²)**（分割が偏ると） | O(n log n) 保証 |
    | 追加メモリ | O(log n)（再帰スタックのみ、in-place） | O(n) の作業領域 |
    | 安定性 | 不安定 | 安定 |

    ### 最悪 O(n²) はいつ起きる？ → 乱択の身近な実例

    partition が毎回「0 : n−1」に偏るとき。素朴に**先頭をピボット**にすると、**整列済み入力という日常的なケースで最悪**を踏む。

    対策：**ピボットをランダムに選ぶ**と、どんな入力でも**期待値 O(n log n)**。[§9 乱択アルゴリズム](AL-Strategies.md#9-ka-core)の「最悪ケースの入力を乱数で均す」の最も身近な実例。決定的な工夫としては median-of-three（先頭・中央・末尾の中央値をピボットに）もある。

    ### なぜ実務で速い・どう使われている

    平均 O(n log n) 勢の中でも**定数倍が小さく、in-place でキャッシュ効率が良い**。C++ `std::sort` の **introsort** は：

    - ベースは quicksort
    - 再帰が深くなりすぎたら **heapsort** に切替（O(n²) 回避の保険）
    - 小区間は**挿入ソート**（→ [Q4](#q4)）

    と、**1つの実装に3パラダイムが同居**する。「[フローは最初の仮説を出す道具](AL-Strategies.md#paradigm-selection)——実際は組み合わせ」の完成形。

    ??? note "補足：選択だけなら quickselect で O(n)"
        「k 番目に小さい値だけ欲しい」なら、partition 後に**片側だけ**再帰すればよい（quickselect）。期待値 O(n)。両側を解く分割統治から、片側だけの減治法（by a variable size）に変わる、Q1〜Q6 の流れと繋がる好例。

    関連: [Divide-and-Conquer / 分割統治法](AL-Strategies.md#3-divide-and-conquer)、[Q4 insertion sort](#q4)、[AL-Foundational §5 ソート](AL-Foundational.md#5-sort)

??? question "Q8. Strassen's algorithm（シュトラッセンのアルゴリズム）について教えて"

    *(2026-06-13)*

    **A.** **2つの n×n 行列の積を、素朴な O(n³) より速く計算する分割統治アルゴリズム**。1969年、「行列積は O(n³) より速くできない」という当時の通念を破った歴史的成果。

    ### 素朴な行列積の復習

    C = A×B の各要素 cᵢⱼ は「A の i 行 × B の j 列」の内積。n² 個の要素にそれぞれ n 回の掛け算 → **O(n³)**。

    ### 分割統治の素直な発想（でも速くならない）

    各行列を4つの (n/2)×(n/2) ブロックに割ると、2×2 行列の積の形になる：

    ```
    | C11 C12 |   | A11 A12 |   | B11 B12 |
    | C21 C22 | = | A21 A22 | × | B21 B22 |
    ```

    ふつうに展開すると C11 = A11·B11 + A12·B21 … と **8回のブロック積**が要る。漸化式 **T(n) = 8·T(n/2) + O(n²)** を解くと結局 **O(n³)** のまま。割っただけでは勝てない。

    ### Strassen の核心：掛け算を 8 → 7 に減らす

    巧妙に作った**7つの積 M₁〜M₇**だけで4ブロックを復元する。掛け算を1回減らす代わりに加減算を増やす取引：

    ```
    T(n) = 7·T(n/2) + O(n²)  →  O(n^log₂7) ≈ O(n^2.807)
    ```

    掛け算1回の節約が再帰のたびに効き、**指数が 3 → 2.807 に下がる**。n が大きいほど差が開く。

    ### パラダイム視点：「部分問題の個数」を削るタイプの分割統治

    同じ [Divide-and-Conquer](AL-Strategies.md#3-divide-and-conquer) でも、ソート系とは効きどころが違う：

    | | mergesort / quicksort | Strassen |
    |---|---|---|
    | 部分問題の**個数** | 2 のまま | **8→7 に減らすのが本体** |
    | 削減が動かすもの | log の底・定数倍 | **指数そのもの**（log₂8=3 → log₂7≈2.807） |

    **マスター定理**（→ AL-Complexity）で「部分問題数 a を1つ減らすと O(n^log_b a) の指数が動く」ことの劇的な実例。

    ### なぜ実務ではあまり使われないか

    - 隠れた**定数倍が大きい**（加減算18回）。クロスオーバー（素朴版を逆転する点）は概ね **n ≈ 数百〜千以上**で、それ未満は O(n³) が速い
    - 数値的に**やや不安定**、追加メモリも要る
    - 高性能ライブラリ（BLAS）はキャッシュ最適化した O(n³) を使うことが多い

    それでも教材として重要なのは、**「掛け算を1回減らす」という代数的工夫が計算量クラスを変えうる**という発見だから。「行列積の指数はどこまで下げられるか」という今も続く研究（理論的下限は現在 ≈ 2.37）の出発点になった。

    関連: [Divide-and-Conquer / 分割統治法](AL-Strategies.md#3-divide-and-conquer)、[Q7 quicksort](#q7)（同じ分割統治でも「個数を減らす」のが Strassen の特徴）

??? question "Q9. Dijkstra's / Kruskal's / Knapsack（貪欲法の3例）について教えて"

    *(2026-06-13)*

    **A.** CS2023 はこの3つを [Greedy](AL-Strategies.md#4-greedy) の例として並べる。狙いは「**貪欲が最適になる/ならないの境界**」を見せること——Knapsack だけ仲間外れ、という構図が肝。

    ### Dijkstra's / ダイクストラ法（単一始点最短経路）

    非負重みのグラフで、始点から全頂点への最短距離を求める。

    - **貪欲の選択**: 「未確定の頂点のうち暫定距離が最小のもの」を選び、距離を**確定**する。一度確定したら更新しない。
    - **なぜ最適か**: 重みが**非負**なので、「今いちばん近い未確定頂点」より短い経路は後から現れない（遠回りして近づくことはない）。
    - **計算量**: 二分ヒープで O((V+E) log V)。
    - **注意**: **負の辺があると壊れる**（確定が早すぎる）→ DP の Bellman-Ford へ。

    ```mermaid
    graph LR
      A((A)) -->|1| B((B))
      A -->|4| C((C))
      B -->|2| C
      B -->|5| D((D))
      C -->|1| D
    ```

    A 始点だと A→B(1)→C(3)→D(4)。直接 A→C(4) より B 経由(3) が短い。

    ### Kruskal's / クラスカル法（最小全域木 MST）

    全頂点を最小総コストで連結する木を作る。

    - **貪欲の選択**: **辺を軽い順にソート**し、「両端が未連結なら採用、閉路を作るならスキップ」を繰り返す。
    - **なぜ最適か**: カット性質（ある分割をまたぐ最小の辺は必ず MST に入る）が正しさを保証。**交換論法**で証明できる。
    - **道具**: 「両端が繋がっているか」の判定に **Union-Find**（→ AL-Foundational）。
    - **計算量**: 辺のソートが支配的で O(E log E)。

    ### Knapsack — ここが分岐点

    同じ Greedy の例に並ぶが、**0/1 版では貪欲は最適にならない**（→ [Q3](#q3) の具体例：密度最大を取ると48、最適は70）。最適になるのは**分割可能(fractional)版**だけ。

    | | 貪欲で最適？ | 理由 |
    |---|---|---|
    | Dijkstra's | ✅ | 非負重み → 確定を後悔しない |
    | Kruskal's | ✅ | カット性質（交換論法で証明可） |
    | Knapsack (fractional) | ✅ | 密度順に詰める、端数も入る |
    | **Knapsack (0/1)** | ❌ | 詰め切れない隙間で破綻 → **DP へ** |

    ### このユニットでの読み方

    3つを並べる本当の意図は、まとめページの [warning「貪欲が最適とは限らない」](AL-Strategies.md#4-greedy) の実演。**貪欲を使うときは「局所最適の積み重ねが大域最適になるか」を必ず検証する**——Dijkstra's/Kruskal's は証明できる側、0/1 Knapsack は反例が作れる側。学習成果6「Evaluate whether a greedy approach leads to an optimal solution」がこの判断力を問うている。

    関連: [Greedy / 貪欲法](AL-Strategies.md#4-greedy)、[Q3 knapsack](#q3)、[AL-Foundational §6 グラフアルゴリズム](AL-Foundational.md#6-graph-algorithms)

??? question "Q10. Instance simplification（インスタンスの単純化）— presort で重複検出"

    *(2026-06-13)*

    **A.** [Transform-and-Conquer](AL-Strategies.md#5a-instance-simplification) の4変換のひとつ。**「同じ問題のまま、扱いやすいインスタンス（入力の状態）に変えてから解く」**構え。

    ポイントは「**変えるのは入力の状態であって、問題そのものではない**」こと。問題を別物に置き換える [problem reduction（§5c）](AL-Strategies.md#5c-problem-reduction) とはここが違う。

    ### 例：重複検出（find duplicates）

    「配列に重複する要素があるか？」を解く。

    **素直な解（Brute-Force）**: 全ペアを突き合わせる。

    ```python
    for i in range(n):
        for j in range(i+1, n):
            if a[i] == a[j]:
                return True   # O(n²)
    ```

    **Instance simplification**: まず**ソートしてから**隣だけ見る。同じ値はソートで必ず隣り合う。

    ```python
    a.sort()                       # O(n log n) ← ここが「単純化」
    for i in range(n-1):
        if a[i] == a[i+1]:         # 隣接チェックだけ O(n)
            return True
    ```

    全体は **O(n log n)** で O(n²) に勝つ。「ソート済み」という**より扱いやすい状態**に変えたことで、隣接比較という単純な走査で済むようになった。

    ### なぜ「presort（事前ソート）」が決め技なのか

    **ソート済みという状態は、いろんな問題を一気に簡単にする**汎用の前処理だから。一度 O(n log n) 払えば後が軽くなる問題群：

    | 問題 | 素朴 | presort 後 |
    |---|---|---|
    | 重複検出 | O(n²) | O(n log n) → 隣接チェック |
    | 最頻値 (mode) | O(n²) | O(n log n) → 連続ランを数える |
    | 最近接ペア（1次元） | O(n²) | O(n log n) → 隣接差の最小 |
    | 2要素の和が k | O(n²) | O(n log n) → 両端から挟む (two-pointer) |

    ### パラダイム視点：前処理コストを後で回収する

    [まとめページの使いどころ](AL-Strategies.md#5-transform-and-conquer)「同値判定・近傍比較を何度も行うなら presort」がこれ。Transform-and-Conquer の3変換の並び：

    | 変換 | 何を変える | 例 |
    |---|---|---|
    | **Instance simplification** | 入力の**状態**（問題は同じ） | **presort して重複検出** |
    | Representation change | データの**表現** | heapsort（配列→ヒープ） |
    | Problem reduction | **問題そのもの**を別問題へ | lcm を gcd に帰着 |

    !!! note "ハッシュを使えば O(n) では？というツッコミ"
        重複検出だけなら set に放り込んで O(n)（[空間で時間を買う](AL-Strategies.md#6-space-vs-time-tradeoffs)）。でも presort の価値は**「ソート済み」が再利用できる**点にある——最頻値・最近接ペア・範囲クエリなど複数の問いに同じ前処理が効く。「1つの問いならハッシュ、複数の順序依存の問いなら presort」が使い分け。

    関連: [Transform-and-Conquer / 変換統治法](AL-Strategies.md#5-transform-and-conquer)、[Q6 Euclid's](#q6)（problem reduction の lcm→gcd と対比）、[空間と時間のトレードオフ](AL-Strategies.md#6-space-vs-time-tradeoffs)
