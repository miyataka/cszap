### 講評

- **弱み**:
    1. **設問の半分にしか答えていない** — Q7「IP アドレスは重複しないのか? **誰が管理しているのか?**」は前半（内部 IP は重複しうる）のみで、後半のグローバルアドレス管理主体（IANA/RIR）に触れていない。
    2. **書きかけ・不正確な例示** — Q8 の IPv6 アドレス形式が「FFFF」を6個並べた例になっており、128 ビット＝16 ビット×**8グループ**という基本形に合っていない。回答も文の途中で切れている。
    3. **未回答** — Q21（RIP/OSPF/BGP の経路決定方式）は空欄。このユニットの中核（ドメイン内/ドメイン間経路制御の違い）が手薄。
- **強み**: Q22（NAT の挙動）は変換の仕組み自体は正確に説明できている。
- **次の一手**: [§3](NC-Routing.md#ip-scalability) を読み直し、IPv4 アドレスの希少性（枯渇）が NAT・CIDR・IPv6 すべての出発点であることを軸に、Q7・Q8・Q22 を1本の線でつなげて再整理する。Q21 は [§1](NC-Routing.md#intra-inter-domain) のドメイン内/ドメイン間の対比表を暗記し直す。

**Q7.** IP アドレスは重複しないのか? 誰が管理しているのか?

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > internal IPは重複させることもできる．（ただし正しく通信できなくなる）

    **模範解答**

    グローバルな IPv4/IPv6 アドレスは重複しないよう **IANA** が地域インターネットレジストリ（RIR）を通じて階層的に割り当てを管理している。一方、`192.168.0.0/16` 等の**私用（プライベート）アドレス**はインターネット上で一意である必要がなく、NAT（[§3-NAT](NC-Routing.md#nat)）によって多数の端末が1つのグローバルアドレスを共有できる。

    **採点 0.4 / 1.0** — 私用アドレスが重複しうるという後半の事実は正しい。だが**設問前半の「グローバルアドレスの一意性」と「誰が管理しているか」に答えていない**（IANA/RIR という管理主体が出ていない）。

**Q8.** IPv6 で Address format はどう変わりますか? IPv4/v6 では何が変わりますか? (IPv6 Address の割り当て方 / MAC Address 解決方法 etc..)

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > IPv6では，128bit rangeになる．FFFF:FFFF:FFFF:FFFF:FFFF:FFFF
    > IPv4からIPv6は

    **模範解答**

    IPv6 はアドレス長が **128 ビット**（16 ビットずつ**8グループ**をコロン区切り、例 `2001:0db8:85a3:0000:0000:8a2e:0370:7334`）で、IPv4 の 32 ビット（約43億）から実質的に枯渇しないだけの空間になる（[§3-IPv4とIPv6](NC-Routing.md#ip-versions)）。割り当ては手動/DHCP に加え自動設定の仕組みを標準で内包し、ヘッダも固定長で簡素化される。NAT が原則不要になり end-to-end の到達性が戻る。

    **採点 0.2 / 1.0** — 「128 bit」という数値は正しいが、示された例は 16 ビット×6個（96 ビット）にとどまり**8グループの基本形になっていない**。回答も文の途中で切れており（「IPv4からIPv6は」で終了）、実質的に未完成。

**Q21.** L3 の RIP, OSPF, BGP では経路はどう決まるか?

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > （未回答）

    **模範解答**

    **RIP・OSPF** はドメイン内経路制御（IGP）で**性能の最適化**（遅延・帯域が最小の道）を目的とする。RIP は距離ベクトル型（隣接ノードにコストだけを教え合う）、OSPF はリンク状態型（全ルータが地図を配り合い各自 Dijkstra で解く）。**BGP** はドメイン間経路制御（EGP）で、**方針の適用**（どの隣人を経由させたいか）を目的とし、AS パスというパスベクタ情報を交換し、コストの最小化より**ローカル優先度**（自 AS の運用方針・顧客/ピア/上流の経済関係）を優先して経路を選ぶ（[§1](NC-Routing.md#intra-inter-domain)、[§3-BGP](NC-Routing.md#bgp)）。

    **採点 0.0 / 1.0** — 未回答。

**Q22.** NATの挙動となぜそれが必要か説明してほしい。

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > NATは内部IPアドレスとportの組みを，NAT GatewayのIPとportに置き換えて外部アクセスを行う．これを行うことで，内部のサーバーのIPを隠蔽できるので，外部からの直接アクセスを防ぐことができる

    **模範解答**

    **仕組み**: 内側の私用アドレスを使う端末が外へ出るとき、送信元アドレスとポート番号を**1つのグローバルアドレス**に書き換えて束ね、戻りパケットは変換表を引いて内側の宛先に戻す（[§3-NAT](NC-Routing.md#nat)）。**必要な理由**: 手元に使えるグローバル IPv4 アドレスが1つしかないのに端末が多数あるという**アドレス枯渇**への対処が第一の目的——NAT は枯渇を「解決」したのではなく**延命**した。副次的に、外から内側の端末を直接指せなくなる遮蔽効果もある。

    **採点 0.6 / 1.0** — 変換の**仕組み**（アドレス＋ポートの書き換え）は正確。ただし挙げている「理由」は副次的効果（遮蔽・外部からの直接アクセス防止）にとどまり、**本来の主目的であるグローバル IPv4 アドレスの枯渇対策**に触れていない。
