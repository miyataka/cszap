!!! info "使い方"

    - 採点は**辛口基準**（本質＋理由付け＋計算量＋正しい用語が揃って満点。簡潔すぎ・論拠が弱い・用語が出ないものは減点。誤答／未回答／書きかけは 0〜0.3）。
    - 既に [Q&A ページ](AL-Complexity-QA.md) で解説済みのトピックは模範解答からリンクする。
    - **再テスト用**: 設問文（コード片を含む）は折り畳みの外に残してあるので、回答を見ずに再挑戦できる。

### 講評

- **強み**: **コードからの計算量導出（Q1）と、ベンチマーク数値からの推定（Q4・Q5）は的確**。「n を倍にして何倍になるか／n を +1 して何倍か」で次数・指数を見抜けている。NP完全への実務対処（Q10）も良い。
- **弱み**:
    1. **再帰の空間計算量（Q2）** — 時間 O(2ⁿ) は正しいが、空間を O(2ⁿ) としたのは誤り。**同時に積まれるコールスタックは最大 n 段だけ**なので空間 O(n)。頻出の誤解。
    2. **メモ化の効果（Q3）** — メモ化フィボナッチは各 n を一度だけ計算するので**時間 O(n)**。O(n²) は数え過ぎ。「メモ化＝再計算の消去で指数→線形」を [AL-Complexity §5](AL-Complexity.md) で再確認。
    3. **NP の語彙（Q7・Q8・Q9）** — 定義・例・3SAT/2SAT がまだ固まっていない。ちょうど [AL-Complexity-QA Q4](AL-Complexity-QA.md#q4) に P/NP/NP完全/NP困難の違いを整理済み。
- **次に上げるなら**: Q2・Q3 の計算量訂正で +約10点、Q6（O(n log n)）と Q7・Q8 の補完で +約15点。

<a id="quiz-q1"></a>

**Q1.** このプログラムの計算量は?（n×n 行列積 matmul）

```javascript
function matmul(n, A, B) {
  var C = new Array(n);
  for (var i=0; i<n; i++) {
    C[i] = new Array(n);
    for (var j=0; j<n; j++) { C[i][j] = 0; }
  }
  for (var k=0; k<n; k++) {
    for (var i=0; i<n; i++) {
      for (var j=0; j<n; j++) {
        C[i][j] += A[i][k] * B[k][j];
      }
    }
  }
  return C;
}
```

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > 時間計算量: 1 + N(1+N) + N·N·N = O(N³ + N² + N + 1) = O(N³)　空間計算量: O(N²)

    **模範解答**

    初期化が二重ループ O(n²)、本体が三重ループ O(n³) → **時間 O(n³)**。確保するのは結果行列 C のみで **空間 O(n²)**（A・B は入力）。

    **採点 0.9 / 1.0** — 時間・空間とも正しい。導出式の初期化部は O(n²) と書くとより明確（結論は同じ）。

    関連: [AL-Complexity §3（基本計算量クラス）](AL-Complexity.md#complexity-classes)

<a id="quiz-q2"></a>

**Q2.** このプログラムの計算量は?（素朴な再帰フィボナッチ）

```javascript
function fib(n) {
  if (n<=1) return 1;
  return fib(n-1)+fib(n-2);
}
```

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > 時間計算量: O(2ⁿ)（n が n-1 に分解されるたびに2倍の計算が必要）　空間計算量: O(2ⁿ)（n が n-1 になるたびに2度のコールスタックが必要）

    **模範解答**

    呼び出し木がほぼ二分木状に広がるので **時間 O(2ⁿ)**（厳密には黄金比 φⁿ ≈ 1.618ⁿ）。一方、**空間は O(n)**。理由は、再帰は深さ優先で実行され、**ある瞬間に積まれているコールスタックは最も深い経路の n 段だけ**だから。「呼び出し回数が 2ⁿ ある」ことと「同時に積まれる段数」は別物。

    **採点 0.5 / 1.0** — 時間 O(2ⁿ) は正しい。**空間 O(2ⁿ) は誤り（正しくは O(n)）**。コールスタックは一度に最大 n 段しか積まれない。

    関連: [AL-Complexity §3](AL-Complexity.md#complexity-classes)、[多項式時間（QA Q2）](AL-Complexity-QA.md#q2)

<a id="quiz-q3"></a>

**Q3.** このプログラムの計算量は?（メモ化フィボナッチ）

```javascript
function fib(n) { return fib_m(n, {}); }
function fib_m(n, memo) {
  if (n<=1) return 1;
  if (memo[n]) return memo[n];
  memo[n] = fib_m(n-1, memo)+fib_m(n-2, memo);
  return memo[n];
}
```

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > 時間計算量: N, N-1, N-2… と変化させるごとに一度ずつ計算すればいいので N+(N-1)+…+1 → N(N+1)/2 → O(N²)　空間計算量: O(N)

    **模範解答**

    各 `fib_m(k)`（k=2..n）は**一度だけ**実 計算され、以後はメモから O(1) で返る。実計算は n 個、各 O(1) → **時間 O(n)**。メモ表と再帰スタックで **空間 O(n)**。メモ化により素朴版の指数時間が**線形**に落ちる。

    **採点 0.4 / 1.0** — 「各 n を一度ずつ計算」という観察は正しいのに、合計を `N+(N-1)+…` と積み上げて O(N²) にしたのが誤り。各計算は **O(1)** なので総和は **O(n)**。空間 O(n) は正しい。

    関連: [AL-Complexity §5（時間と空間のトレードオフ＝メモ化）](AL-Complexity.md)、[Day2 Q8（時間⇄空間）](AL-Strategies-Quiz.md#quiz-q8)

<a id="quiz-q4"></a>

**Q4.** あるプログラムの引数 n を変えてベンチマークを取ると、使用メモリはこうなった。空間計算量は何と見積もる?

> n=1,10,100,1000 ⟹ 100, 100, 100, 104 MB ／ n=10000, 20000, 50000, 100000, 200000 ⟹ 501, 1703, 10106, 40113, 160126 MB

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > 空間計算量: O(N²)

    **模範解答**

    小さい n では定数の下駄（約100MB）が支配的。大きい領域で見ると **n を2倍にすると使用量が約4倍**（20000→200000 で ×94≈×100＝10倍²、50000→100000 で 10106→40113 ≈ ×4）。倍々で4倍＝**O(n²)**。

    **採点 0.9 / 1.0** — 正しい。「n 倍増で約4倍だから O(n²)」と一言根拠を添えれば満点。

    関連: [AL-Complexity §4（経験的測定で理論を検証）](AL-Complexity.md)

<a id="quiz-q5"></a>

**Q5.** あるプログラムの引数 n を変えてベンチマークを取ると、実行時間はこうなった。時間計算量は何と見積もる?

> n=1..5 ⟹ 12,18,27,42,69 ms ／ n=6..10 ⟹ 120,219,414,801,1572 ms ／ n=11..15 ⟹ 3111,6186,12333,24624,49203 ms

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > O(2ⁿ)

    **模範解答**

    n を **+1 するごとに実行時間が約2倍**（後半では 24624→49203 ≈ ×2.00）。加法的な増分で乗法的に伸びる＝**指数時間 O(2ⁿ)**。

    **採点 0.9 / 1.0** — 正しい。「n を +1 で約2倍だから 2ⁿ」と根拠を添えれば満点。

    関連: [AL-Complexity §3（O(2ⁿ) 指数）](AL-Complexity.md#complexity-classes)

<a id="quiz-q6"></a>

**Q6.** あるプログラムの引数 n を変えてベンチマークを取ると、実行時間はこうなった。時間計算量は何と見積もる?

> n=10,50,100,200 ⟹ 12,49,107,236 ms ／ n=500,1000,10000 ⟹ 679,1502,19939 ms

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > （未回答）

    **模範解答**

    **O(n log n)**。判定: `時間/n` を見ると 1.2 → 1.0 → 1.07 → 1.18 → 1.36 → 1.50 → 1.99 と**ゆっくり増える**（純粋な O(n) なら一定、O(n²) なら急増）。`時間/(n·log₂n)` を取ると 10≦n≦10000 で約 0.15 に**ほぼ一定**に収束する。これが O(n log n) の指紋（マージソート・ヒープソート・高速なソート系）。

    **採点 0.0 / 1.0** — 未回答。線形（時間/n が一定）と二乗（急増）の中間で、`時間/(n log n)` が一定になる感覚を掴みたい。

    関連: [AL-Complexity §3（O(n log n) 線形対数）](AL-Complexity.md#complexity-classes)、[ソートの壁 Ω(n log n)（Foundational-QA Q11）](AL-Foundational-QA.md#q11)

<a id="quiz-q7"></a>

**Q7.** NP問題・NP完全・NP困難の定義を説明

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > NP問題: 非決定的多項式問題。　NP完全: （空欄）　NP困難: （空欄）

    **模範解答**

    - **NP**: 答えを与えられれば**多項式時間で検証できる**問題（＝非決定性多項式時間）。
    - **NP完全**: NP に属し、かつ **NP の全問題がそこへ多項式時間で帰着できる**（NP の中で最難）。
    - **NP困難**: NP の全問題が帰着できる（最難の**下界**）が、**NP に属するとは限らない**（決定不能問題や最適化版も含む）。

    関係は **NP完全 = NP困難 ∩ NP**。

    **採点 0.2 / 1.0** — 「NP＝非決定性多項式」の語は出たが一行のみ。NP完全・NP困難が空欄。

    関連: [P・NP・NP完全・NP困難の違い（QA Q4）](AL-Complexity-QA.md#q4)、[AL-Complexity §6](AL-Complexity.md#tractability)

<a id="quiz-q8"></a>

**Q8.** 3SAT の複雑性クラスは? 2SAT に書き換えると?

??? note "回答・模範解答・採点を開く"

    > n 種類の変数で、3つ以下の変数（かその否定）の OR を多数 AND で繋いだ式 `((x∨¬y∨z) ∧ (¬x∨y∨¬z) ∧ …)` を TRUE にする割当を探す問題（3SAT）。これを「2つ以下の…」に書き換えると（2SAT）?

    **本人の回答**

    > （未回答）

    **模範解答**

    - **3SAT は NP完全**（最初に NP完全と示された SAT の代表形。[Cook–Levin の定理](AL-Complexity.md#tractability)）。
    - **2SAT は P（多項式時間で解ける）**。各節 `(a∨b)` を含意 `(¬a⇒b), (¬b⇒a)` に変換した**含意グラフ**を作り、強連結成分 (SCC) を求めて「ある変数 x と ¬x が同じ SCC に入らないか」を見るだけ＝線形時間。
    - 「節あたりのリテラルが2 か 3 か」という小さな差が、**P と NP完全の崖**を分ける有名な例。

    **採点 0.0 / 1.0** — 未回答。3SAT=NP完全 / 2SAT=P の対比は計算量理論の定番。

    関連: [SAT ソルバ（AL-Strategies-QA Q14）](AL-Strategies-QA.md#q14)、[AL-Complexity §6](AL-Complexity.md#tractability)

**Q9.** NP完全な問題の例を3つ

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > 巡回セールスマン問題、ナップサック問題、（3つ目は空欄）

    **模範解答**

    **SAT/3SAT、巡回セールスマン問題（判定版）、0/1 ナップサック（判定版）**。ほかに頂点被覆、クリーク、グラフ彩色、ハミルトン閉路、部分和問題など。なお「TSP の最適経路を1つ出せ」という最適化版は厳密には NP困難（NP完全は判定問題の用語）。

<a id="quiz-q10"></a>

**Q10.** NP完全な問題に出会ったら、どうアプローチするか

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > どれくらいのインプットがあるか確認し、問題を別の問題に帰着できないか調査する。不可能で、入力サイズが小さいなど可能なら厳密解を。入力サイズが大きいなら近似解で要件を満たせないかを探る。

    **模範解答**

    ① **入力規模の確認**。② **既知の易しい問題に帰着できないか**（特殊構造があれば多項式で解けることも）。③ 入力が小さければ**厳密解**（DP・分枝限定）。④ 大きければ**近似アルゴリズム／ヒューリスティック／乱択**で要件を満たす。⑤ 擬多項式 DP が効く場合も（小さい W の 0/1 ナップサック等）。これは [AL-Complexity §6「NP完全だと分かったら何をするか」](AL-Complexity.md#tractability) と一致。

    **採点 0.8 / 1.0** — 帰着調査→入力サイズで厳密/近似を分岐、という実務の型を押さえている。擬多項式 DP・固定パラメータまで触れると満点。

    関連: [AL-Complexity §6（実務の出口）](AL-Complexity.md#tractability)、[Day2 Q12（実務でTSP）](AL-Strategies-Quiz.md#quiz-q12)
