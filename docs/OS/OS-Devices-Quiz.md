### 講評

- **強み**: Q6（テープ・HDD・SSDの比較）は満点。コスト・容量・速度・寿命という4軸で正確に整理できている。
- **弱み**: Q10（I/O方式の使い分け）で**「メモリマップド I/O」と「ファイルの mmap」を混同**——前者は「デバイスのレジスタをメモリアドレス空間に写像する」仕組み、後者は「ファイルをメモリアドレス空間に写像する」仕組みで、字面が似ているだけの別物。「ポートマップド I/O」も IPC 的な説明になっており、実際は専用の I/O アドレス空間を介してデバイスレジスタへアクセスする方式。Q11（デバイスドライバの振り分け）・Q12（`ioctl`）は未回答——このユニットの中でも実装寄りの細部（メジャー/マイナー番号、`ioctl` の役割）が手薄。
- **次の一手**: 「メモリマップド I/O」と「mmap（ファイルのメモリマッピング）」は**別々に**インデックス化して覚え直すのが効率的。「レジスタを地図に載せる」 vs 「ファイルを地図に載せる」で対比するとよい。Q11・Q12 は [OS-Devices §1](OS-Devices.md#device-layers) の「すべてはファイル」抽象を起点に、デバイスファイルの識別と制御の仕組みを補強するのが次の一手。

**Q6.** テープ、HDD、SSDを比較して欲しい

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > テープは，とても安価で，大容量を長期間保存するのに向いている．読み取り・書き込みの速度はおそく，日常使いには不向き
    > HDDは，安価で，大容量をアクセス可能な状態で保管しておくのに向く．読み取り・書き込みはテープより速く，SSDよりは遅い
    > SSDは，比較的高価で，ある程度までの容量を日常使いするのに向く，読み取り・書き込みは高速．書き込みの回数の上限があるので，比較的寿命が短い

    **模範解答**

**テープ**（本文未収録・一般知識の補足）: 磁気テープに順次アクセスのみで記録。単位容量あたり最安・長期保管に強いが読み書きは低速——日常使いではなくアーカイブ／バックアップ用途。**HDD**（[OS-Devices §4](OS-Devices.md#persistent-storage-history)）: 回転する磁性ディスクと機械的な**シーク**・**回転待ち**を伴う。安価に大容量をオンラインで持てるが、テープより高速・SSDより低速。**SSD**（同§4）: 可動部品を持たずフラッシュメモリで動作、シーク時間がほぼゼロでランダムアクセスが高速。**書き込み回数に上限**があり、**ウェアレベリング**（セル間の摩耗の平準化）が必要で、単位容量あたりのコストは相対的に高い。

    **採点 1.0 / 1.0** — 満点。コスト・容量・速度・寿命の4軸すべてで正確。特にSSDの「書き込み回数の上限→寿命」という因果は[OS-Devices §4](OS-Devices.md#persistent-storage-history)の記述と一致している。

**Q10.** デバイスとデータをやり取りする方法は、Port mapped I/O, Memory mapped I/O, DMA、割込みなどがあるが、どのような時に使うのか?

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > port mapped I/O: OS外も含め，別プロセスとやりとりするときなどに用いられる．
    > memory mapped I/O: ファイルをメモリに割り当てるような形で用いる
    > DMA: 直接メモリを書き換えるときに用いる．
    > 割り込み: デバイスからの入出力を処理するために用いる．あるいはタイマーなど定期的な処理に用いられる

    **模範解答**

    **ポートマップド I/O**（本文未収録・一般知識の補足）: CPU が持つ専用の **I/O アドレス空間**（メモリアドレス空間とは別）を介し、`IN`/`OUT` のような専用命令でデバイスレジスタにアクセスする方式。メモリアドレス空間を消費しない代わり専用命令が要る、x86 の伝統的な方式。**メモリマップド I/O**（[OS-Devices §3](OS-Devices.md#dma-io)）: デバイスのレジスタを**通常のメモリアドレス空間の一部**に割り付け、普通のロード/ストア命令でアクセスする方式——専用命令が要らず現代の主流。**DMA**: 専用コントローラが CPU を介さずメモリ⇔デバイス間を直接転送し、**大量データ転送で CPU 負荷を大きく下げる**（転送完了時に1回だけ割り込み）。**割り込み**: デバイスが完了を非同期に知らせる仕組みで、CPU をポーリングのビジーウェイトから解放する（[OS-Principles §6](OS-Principles.md#interrupts) のタイマー割り込みと同型）。使い分けの軸は「**転送量**（大きいほどDMA有利）」「**CPUを張り付かせたくないか**（割り込み駆動 vs ポーリング）」。

    **採点 0.3 / 1.0** — 割り込みの説明はおおむね妥当。しかし**ポートマップド I/O を「別プロセスとやりとり」という IPC 的な説明にしてしまっており誤り**（実際は専用I/Oアドレス空間を介したデバイスレジスタへのアクセス方式）。**メモリマップド I/O を「ファイルをメモリに割り当てる」としているのも誤り**——それは[OS-Memory §8](OS-Memory.md#virtual-memory-services)/[OS-Advanced-Files §2](OS-Advanced-Files.md#mmap)の `mmap`（ファイルのメモリマッピング）であり、メモリマップド I/O は**デバイスのレジスタ**をメモリアドレス空間に写像する別の仕組み。字面が似ているための混同。DMAは「直接メモリを書き換える」で方向性は合っているが、CPU負荷軽減という利点への言及がない。

**Q11.** OSは、ユーザプログラムがどのデバイスドライバにリクエストをしているかどう判断するのか?

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > （未回答）

    **模範解答**

    （本文未収録・一般知識の補足）[OS-Devices §1](OS-Devices.md#device-layers) の「すべてはファイル」抽象（UNIX系では `/dev/sda`, `/dev/tty` などのデバイスファイル経由でデバイスにアクセスする）を土台に、実装レベルでは各デバイスファイルに**メジャー番号・マイナー番号**という2つの整数が結び付けられている。カーネルは起動時／ドライバロード時に「メジャー番号 → ドライバの操作関数群（read/write/ioctl の実体）」という**ディスパッチテーブル**を構築しており、プログラムがデバイスファイルを `open` すると、カーネルはそのファイルのメジャー番号を引いて**どのドライバが担当するか**を判断する。マイナー番号は同じドライバが管理する**複数デバイスインスタンス**（例: 複数のディスクパーティション）の中でどれかを区別するために使う。

    **採点 0.0 / 1.0** — 未回答。

**Q12.** ioctl system call は何をしているのか?

??? note "回答・模範解答・採点を開く"

    **本人の回答**

    > （未回答）

    **模範解答**

    [OS-Devices §1](OS-Devices.md#device-layers) は「デバイスドライバはコントローラのレジスタ操作を OS 共通のインタフェース（read/write/ioctl）に翻訳する」と `ioctl` の存在に触れるのみで、詳細は本文未収録（以下は一般知識の補足）。`read`/`write` は「バイト列の読み書き」という汎用モデルに収まる操作しか表現できないが、デバイスにはそれに収まらない**固有の制御操作**（例: CD-ROM のイジェクト、ネットワークインタフェースの設定変更、ディスクのブロックサイズ取得）が多数ある。`ioctl` はそれらを「**コマンド番号 + 任意の引数バッファ**」という一般化された形でデバイスドライバに渡すためのシステムコールで、各ドライバがコマンド番号ごとの処理を個別に実装する、いわば read/write の抜け道的な**汎用制御チャネル**。

    **採点 0.0 / 1.0** — 未回答。
